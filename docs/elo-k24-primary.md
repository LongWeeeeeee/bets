# Основной ELO состава: K24

По решению пользователя после [E-297](experiments/E-297-elo-formula-winrate-audit.md)
основной рейтинг состава переведён на независимый K24. Он используется в
`get_matchup_summary`, Telegram и существующих правилах, читающих этот summary.
Пороги правил не меняются. Обученная ML сохраняет прежние признаки и веса.

## Формула и время

Новый игрок начинает с 1500. Рейтинг состава — среднее пяти игроков.
Для разности рейтингов Radiant−Dire:

```
P(Radiant) = 1 / (1 + 10 ** (-difference / 400))
delta = 24 * (radiant_win - P(Radiant))
Radiant: каждый игрок += delta
Dire: каждый игрок -= delta
```

Обновление происходит по завершённой карте. K24 не использует tier-поправки,
roster-weight, decay, uncertainty, side bias и бонус за sweep из hybrid.
Поэтому слабая лига не создаёт отдельный локальный рейтинг состава.

Прогноз на время начала карты использует только результаты с временем
завершения **строго меньше** начала. В состоянии сохраняются 14 дней
обратимых обновлений. При запросе внутри этого окна поздние обновления
вычитаются; до границы покрытия рейтинг недоступен. Порядок результатов
контролируется: старый результат внутри покрытия вставляется с отменой и
пересчётом последующих K24-обновлений. Hybrid при этом не пересчитывается.
Результат до границы покрытия или неизвестный исход в пересчитываемом хвосте
делает K24 недоступным и блокирует публикацию состояния при ребейзе.
Индекс membership снимка хранит 14 дней; удержание tombstone остаётся 7 дней.

## Контракт чтения

- `k24_lineup_summary`: source=`elo_composition_k24`,
  rating_source=`composition_k24`; Telegram — «ELO состава (K24)».
- Нужны две полные пятёрки разных account ID без пересечения сторон.
- `prematch_lineup_summary` остаётся реализацией обученного `hybrid_strength`.
  Признаки ML `elo`/`opp_elo`, `last_model_elo` и веса не меняются.
- Старый snapshot без явной K24-схемы требует offline-пересборки.
  Повреждённый выбранный live-state не подменяется базовым рейтингом.
- Таблица рангов использует K24 последних известных составов. Это snapshot-
  ранги; для запроса до/на время snapshot ранг не выдаётся.
- Снимок имеет новую replay-подпись `finished_results_v1+k24_v1`;
  array sidecar и live delta версионированы отдельно.

## Проверки

`ELO/tests/test_k24_primary.py` проверяет независимость формулы от hybrid,
строгое время, legacy/malformed состояния, full/array/delta roundtrip,
перестановку сторон, ранги и источник live-данных. Контракт ML проверяется в
`base/tests/test_team_elo_contract.py`.

Команда локальной проверки:

```
venv_catboost/bin/python3 -m pytest ELO/tests base/tests/test_team_elo_contract.py -q
```

Полная staging-проверка запускается через общий executor. Харнесс
`runtime/experiments/elo/stage_k24_primary.py` строит отдельный snapshot,

NPZ, затем переносит **копию** серверного ledger в отдельные файлы. Все
артефакты остаются в output каталоге задания; активные файлы не заменяются.

## Переключение production

Нужны совместимые код, пересобранный snapshot и успешно перенесённый ledger.
Перед заменой сохраняются исходные состояния и ожидающие карты. На остановленном
сервисе перенос повторяется для свежего ledger; только после успешной проверки
заменяются файлы и создаётся совместимый sidecar. Ошибка порядка — причина
остановить миграцию, а не отбросить результаты или ослабить проверку.

Деплой и рестарт требуют отдельного согласованного действия по
`docs/RUNTIME_RULES.md`. Локальная реализация и staging не означают, что
production переключён. Также нельзя включать в деплой чужие ожидающие коммиты
без согласования их области.

## Граница вывода о winrate

Это реализация выбранного по E-297 кандидата, а не новый независимый тест
прироста WR. В holdout E-297 K24 дал 425/660 (64.39%) против 416/660 (63.03%);
парный доверительный интервал разницы включал ноль. Tier-3: 326/514 (63.42%)
против 315/514 (61.28%). Эти результаты не доказывают рост будущего WR или ROI.
