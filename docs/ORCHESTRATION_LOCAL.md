## Общая доска

Оба приложения используют одну реализацию в `~/.claude/hooks/`:
`board-shared.mjs`, `board-inject.mjs`, `board-gate.mjs`. Корень определяется
через Git common directory: вложенные каталоги и linked worktree используют
основную `.beads/beads.db`. Независимый вложенный репозиторий не наследует
чужую доску. Содержимое чатов автоматически общим не становится.

Стартовый хук печатает путь БД и actor `codex:<session_id>` либо
`claude:<session_id>`. Перед изменениями нужно прочитать задачу, получить её
через атомарный `update <id> --claim` и указать свои файлы. Чужой claim нельзя
перезаписывать. Один файл — один автор; claim не заменяет файловую блокировку.

После каждого существенного завершённого шага, включая read-only находки,
обновляйте issue через `bd update <id> --notes` перед долгим запуском,
compaction, паузой или ответом пользователю; достаточно одного компактного
текущего checkpoint, не записи после каждого вызова. В нём: workspace/branch,
доказательства, незавершённое, точное следующее действие, живые PID/логи и
статус рестарта, свои файлы и блокеры. Startup hook сначала показывает
unfinished notes, затем перед правкой нужен `bd show <id> --json`. При handoff
после checkpoint и остановки правок выполните `bd update <id> --status open
--assignee '' --add-label handoff`; новый клиент проверяет cwd/Git/runtime,
выполняет `bd update <id> --claim --remove-label handoff` и снимает handoff.
Возрастом нельзя забирать активного владельца; после crash проверьте Git и логи.
Gate проверяет свежесть после последнего наблюдаемого edit: handoff принят,
если issue open, assignee пуст, есть label `handoff`, notes записаны, а последний
actor совпадает с releasing session. Предыдущие версии notes сохраняются в
Beads event data; текущую запись заменяйте компактным полным checkpoint,
сохраняя незакрытые findings. Для SQLite board `bd history` не используется.
Если незавершённый turn заканчивается без live writer, сохраните checkpoint и
освободите handoff; при живом writer или background job claim сохраняется.

После изменений Stop проверяет обновление задачи текущим actor, её assignee
и новый ID события в SQLite. Обновление другой сессии не засчитывается.
Проверка замечает прямые Edit/Write/apply_patch и явные sed/perl с `-i`;
произвольные shell/Python-записи требуют соблюдения протокола самим агентом.
При ошибках координация явно помечается degraded; число повторных требований
ограничено двумя. Хуки не являются границей безопасности.

Beads работает напрямую с SQLite и выгружает JSONL без демона. В обоих проектах
установлено `no-daemon: true`. Два старых демона остановлены, повторное чтение
БД не запустило их. `.beads/` остаётся локальной: никаких `bd sync` или push.

## Контекст и лишняя работа

- Codex: `model_auto_compact_token_limit = 160000`.
- Claude: `autoCompactWindow = 200000`; подсказки о контексте работают для всех
  моделей, на 150000 и 180000 токенов, с повторным предупреждением после compaction.
- Автокоммиты всего дерева и принудительный reflect-gate отключены в регистрации
  и по умолчанию в самих скриптах. Коммиты выполняются явно по своим файлам.
- Короткие независимые задания субагентам; нет обязательной квоты делегирования
  или цепочки ролей. Выбранные модели и reasoning не менялись.

## Находки от других агентов

Занятая задача не блокирует весь проект. Любая сессия Codex или Claude может
добавить находку к чужой карточке без claim и без перезаписи её checkpoint:

```sh
bd --no-daemon --db <canonical-db> --actor <session-actor> comments add <issue-id> --author <session-actor> -f <finding-file>
bd --no-daemon --db <canonical-db> comments <issue-id> --json
```

В комментарии: находка, источник/проверка, границы уверенности, предлагаемый
следующий шаг. Исправления добавляются новым комментарием. Независимое знание
можно записать в новую незанятую карточку с label `kb`; claim нужен при начале
работы над ней, а не при сохранении информации. Чужие notes, description,
status и assignee остаются под управлением владельца. Комментарий сам по себе
не требует ещё одной служебной задачи. Перед продолжением/закрытием владелец
читает comments, учитывает релевантные находки в notes и отмечает их обработку
ответным комментарием. Автоматического пробуждения или опроса нет.

Установленная версия Beads хранит комментарии отдельно и не добавляет их в
таблицу событий `events`. Поэтому существующий Stop-gate уже сохраняет нужное
поведение: комментарий не заменяет checkpoint после правки и не отменяет
сохранённый checkpoint или handoff. Код gate менять не потребовалось.

Проверка: `venv_catboost/bin/python3 ~/.claude/hooks/tests/test_board_contributions.py`.
Восемь сценариев проверяют запись двух авторов одновременно, сохранение
notes/status/assignee, checkpoint/handoff и подсказку о комментариях для обоих
harness. С прежним inject отсутствовала только новая подсказка; проверки
владения проходили. После изменения также прошли прежние 76 сценариев доски
и startup-проверка контрольных точек. Это проверки CLI и обработчиков,
а не свидетельство автоматического чтения комментариев каждым живым агентом.
