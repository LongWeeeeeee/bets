# E-374. Поминутная модель против цены Winline

Карточка ingame-5mgd. Повод — владелец 10.10: «либо нужна поминутная модель» (после E-372, где стадийные гейты ставок на андердога сработали по проценту побед, но не в деньгах).

## Вопрос

Важно не «предсказывает ли поминутная модель победу» (предсказывает: E-347), а «знает ли она что-то сверх цены Winline в ту же минуту». Только это даёт деньги.

## Прогноз и правило решения (записаны до прогонов, `.omc/decisions.md` 10.10)

- **Прогноз.** Прирост log loss против рынка (Q1) в пределах −0,01…+0,01, ДИ через ноль; ставки на расхождение ≥0,05 — ROI в пределах ±10 %.
- **Правило.** Поминутную модель для ставок строим (сначала тенью), только если одновременно:
  - сводный OOT-прирост log loss против рынка по Q1 > 0 и ДИ не задевает ноль;
  - ROI ставок на расхождение ≥0,05 > 0 и по Q1, и по Q3.

## Исходы (M3)

Исходов не было у 72 из 136 карт M2 и у 78 из 544 карт M1. Это были в основном 06–10.10: снимки исходов заморожены 06–08.10, а ночная перебазировка ELO с 03.10 закрывает карты без `radiant_win`.

OpenDota `proMatches` + `teams/<id>/matches` закрыл 46 карт. Сопоставление: пара team_id, окно времени [start − 10 мин; start + duration + 25 мин], без нечёткого сравнения имён. Контроль на уже известных картах: совпало 232, расхождений 0. Осталось без исхода 28 карт M2 и 32 карты M1 (тир-3 вне OpenDota pro).

Песочница Codex сеть не видит (DNS), поэтому сбор шёл локально. urllib получил Cloudflare 1010 — блок подписи Python-urllib, не квота. Помог браузерный UA, как в `base/opendota_research.py`.

## Контроль без модели: фаворит и андердог по живой цене

| ELO-андердог (ΔELO ≤ −50) | 249, 70, 3,37, **−32,5 % [−46; −18]** | 271, −33,2 % [−45; −20] |

| андердог рынка | 333, 100, 3,43, −17,8 % [−31; −4] | 376, −12,9 % |

**Механизм.** По живой цене Winline ELO-андердогу без маржи положено 35,7 %, а выигрывает он 28,1 %. Модель M4 даёт ему 32,0 % — ближе к правде, но тоже выше. При перевесе андердога (кэф < 2) он выигрывает 45,9 % при цене 59,3 %. Рынок переоценивает ранний перевес слабой команды и недооценивает силу (ELO). Отсюда и у M4 модельные ставки на андердога в минусе (δ ≥ 0,05: Q1 −35,9 % [−61; −8], n 80), а на фаворита — в плюсе (δ ≥ 0,08: Q1 +18,8 % [+3; +37], n 115; Q3 +13,2 % [−0,0; +26,8], n 155). Фаворитный срез выбран после взгляда на данные (16 групп × 2 цены), поэтому это идея на проверку, а не результат.

## Решение

- **Поминутную модель для ставок не строим.** Правило не выполнено ни в одном узле: сводный прирост против рынка ≤ 0 везде, ROI δ 0,05 по Q3 отрицательный.
- **E-347 в бою остаётся строкой** (служебный бот + `runtime/ml_minute_shadow.jsonl`). Она не мешает и копит данные.
- **Идея ingame-cccu** (пересчёт ~10.11): ставка на ELO-фаворита, когда поминутная модель выше рынка на ≥0,08. Заморозить `perminute_v1.json` и посчитать на тиках после 10.10.
- **Ставки на ELO-андердога** (запрет снят владельцем 09.10, ingame-8ht2): безмодельная выборка 249 карт — −32 %, андердог впереди — −17…−20 %. Сами доставленные диспетчером ставки на андердога в эре all7m — −7 % (Q1, n 17, ДИ [−57; +48]), то есть пока неразличимы. Это вопрос владельцу (вернуть `ML_DISPATCH_WIN_UNDERDOG_BLOCK=1` и без снятия E-365 `ML_DISPATCH_WIN_UNDERDOG_REALIZED_RELEASE=0`). Перепроверка по доставленным — ingame-3e0e.

## Где искать ошибку

- **Ориентация цен.** Все тики — в ориентации Radiant (`side`=radiant у 3 498 из 3 498). `implied_no_vig` = (1/p)/(1/p + 1/q) сверен на 1 431 котировке из 1 431. Q3 берёт будущую котировку (до 180 с) — это стресс-проверка, не исполнимая цена.
- **Исходы.** Ключи леджера — на карту (`<url>.0`, 177 ссылок, ни у одной двух карт). Исход карты 1 в карты 2–3 не протекает. Расхождений между источниками 0. OpenDota-исходы — `outcomes/outcomes_extra.jsonl` и `outcomes/control.json`.
- **Признаки M4.** В журнале нет киллов: основная модель без них, киллы только из корпуса. «All» в журнале статичный из драфта. 307 тиков без NW исключены. Драфт-логиты корпуса до 21.09 in-sample для all7m — как в боевом рецепте.
- **Первый тик на карту.** Журнал пишет тик, когда диспетчер решает. Это не случайная минута, а момент оценки, чаще всего 10–15′ и 0–5′.
- **Многократность.** M4 — 16 групп × 2 цены × 4 δ; контроль — 4 базовых ставки × окна. ДИ поточечные. Фаворитный срез — после взгляда на данные.
- **Бутстрап M4 на v2** выдал предупреждения переполнения в matmul (`run.py:312`), но `verify.py` прошёл (exit 0) и сводные числа совпали с `verify`.
