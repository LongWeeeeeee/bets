# E-342 — Правило владельца: ставка на килы 5-15 при ★ ML Laning и согласных ранних моделях (26.09.2026)

**Статус:** правило владельца, внедряется в `base/ml_dispatch.py` (rule `kills_lane_early_window`).
Офлайн-замера попадания НЕТ — ниже только частота срабатывания на живом логе решений
и ближайший по смыслу чужой замер.

## Правило

Слова владельца (26.09.2026): «если у нас ML Laning имеет star сигнал и 1 или оба early nw
early win показывает на эту же команду и ни 1 из них не показывает на противоположную то мы
отправляли ставку на 5-15 киллы».

- ★ = уверенность ≥ `ML_DISPATCH_MIN_CONF` (0.60), тот же порог, что и звезда в панели.
- ML Laning★ за сторону S; хотя бы одна из Early NW / Early Win со ★ за S; ни одна из них
  не имеет ★ за другую сторону (Early Win 0.54 за другую сторону — не мешает).
  Трактовка «показывает» = ★ выбрана по прецеденту правила kills_early от 19.09
  («Early NW ≥ порога за A, Early Win не ≥ порога за другую сторону»).
- Рынок `kills_window`, окно `5_15` (открыто, пока `game_time + 180 ≤ 300`, то есть до 2:00
  игрового времени; в ML-тике обычно отправка на −79 с, до старта карты).
- Не зависит от ELO/андердога, Late, All, kills30, NW.
- Общие гейты тика сохраняются: Tier-1 (`KILLS_REQUIRE_TIER1_TEAM`, ставки на килы только
  если в матче есть команда Tier-1), `position_mismatch`, дедуп реестра. В одном тике —
  не больше одной ставки `kills_window`; новое правило не ставит, если окно уже ушло за
  любую сторону. Межтиковая дыра старых путей андердога и late-conflict 4.3 закрыта
  по `ingame-6ox6`: после отправки окна за одну сторону они пропускают окно за другую.
  Откат только этой правки — `ML_DISPATCH_KILLS_WINDOW_ONE_SIDE=0` (`false`/`off`).
- Откат без деплоя: drop-in `ML_DISPATCH_LANE_KILLS=0`; окна — `ML_DISPATCH_LANE_KILLS_WINDOWS`
  (по умолчанию `5_15`).

### Механизм расхождения (что верю и чем проверено)

- Ранние модели переносятся с офлайна на живые карты (Early NW 57,3 → 55,8 %, обе ★ 58,7 → 57,6 %), а Laning — нет
  (56,4 → 46,0 %, разница ~3,3 σ). Значит, ломается не исход и не реплей, а связь «★ Laning → килы 5-15» вживую.
- Сторону Laning не перепутали: вживую ★ Laning угадывает знак NW на 10-й минуте в 58,4 % (n=214; офлайн 66–71 %).
  Гипотеза «проигравшая линии сторона добирает килы ротациями» ОПРОВЕРГНУТА: вживую лидер по килам 5-15 совпадает
  с лидером NW@10 на 238/318 картах (74,8 %). Механизм проще: вживую laning-модель на ~10 пп слабее офлайна по своему
  таргету, а 58 % по NW@10 при связи 75 % дают ≈0,58·0,75 + 0,42·0,25 ≈ 54 % по килам без ничьих — на подвыборке с
  тиком NW@10 наблюдено 97/184 = 52,7 %. Ничьи (7 %) опускают это до ~50 % строгого попадания.
- Офлайн-цифры завышены и по таргету laning (≈68 % против 58 % вживую) — та же картина, что в памяти о завышенных
  офлайн-числах предматча.

### Где искать ошибку

- Live-выборка мала: CI правила 43–59 %, критерий опровержения (верх CI < 55,6 %) формально НЕ выполнен.
- Ничьи: как Winline рассчитывает ничью в окне — не проверено; без ничьих правило 55,1 %.
- Tier-1 гейт и реестр: реплей берёт все карты, отправлено меньше (17 ставок правила).
- Пары «вердикты первого тика»: у 5 карт из 458 нет тика до 120 с — исключены.

## Решение владельца и выкатка (05.10.2026, карточка ingame-h9b5)

Владелец выбрал «Панель ≥ 0,60 вместо Laning». В бою с **05.10.2026 21:30:17 MSK** (коммит `c6af65c7`,
задача доставки `panel-kills-5-15-20261005`):

- новое правило `kills_panel_window` (`base/ml_dispatch.py::_evaluate_kills_panel`): панель `w_5_15`
  (строка «🤖 ML: окно 5-15») с калиброванной уверенностью ≥ 0,60 → одна ставка `kills_window` 5_15 на её
  сторону; без фильтра ok/blocked/fill (как в замере); битая вероятность (NaN, вне [0,1]) → отказ
  `panel_kills_bad_verdict`; env `ML_DISPATCH_PANEL_KILLS` (1), `_MIN_CONF` (0.60), `_WINDOWS` (5_15);
- правило Laning `kills_lane_early_window` выключено по умолчанию (`ML_DISPATCH_LANE_KILLS=0`, откат `=1`);
- в проде предматчевая модель выключена, вердикт панели идёт тем же каналом, что kills30
  (`_off_auxiliary_panels` → `functions.py` `_fallback_details` → `details` тика); журнал решений теперь
  пишет `verdicts.panel_w_5_15` — следующий замер попадания не требует журнала панели.

Проверка перед выкаткой (`runtime/experiments/star-dispatch/e342_panel_anytick.py`): боевое правило
(первая строка панели с уверенностью ≥ 0,60, пока окно открыто) даёт те же карты, что замер по первой строке:
195 карт, 64,6 % [57,7; 71,0]; ни одной карты, где ставка ушла бы только на поздней строке. Tier-1 гейт край не
снимает: карты, где гейт уже срабатывал, 67,9 % (n=28), остальные 62,9 % (n=170).

Где искать ошибку: (1) путь андердога 5_15 идёт раньше панели — на 13 из 73 карт с его ставкой панель ≥ 0,60
была за другую сторону (сторона панели взяла 7 из 11), там теперь уходит ставка андердога, а панельная
откладывается — это вне решения владельца; (2) ставок на окно нет пола по кэфу (как и раньше);
(3) замер — 12.09–05.10 на живых картах, без кэфов: попадание, не ROI. Пересчитать по `verdicts.panel_w_5_15`
и доставленным `kills_panel_window` через ~2 недели (~19.10).

### Выключен путь андердога 5-15 (05.10.2026, 21:45:50 MSK, коммит `1d88e705`)
