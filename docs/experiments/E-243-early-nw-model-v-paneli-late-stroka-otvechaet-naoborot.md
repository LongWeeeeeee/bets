# E-243. Early-NW модель в панели: late-строка отвечает на этот вопрос наоборот

- **Дата:** 2026-09-01 (alex: «введи эту ml модель в прод перед 🕑 Late ML-модель»
  + «обучи модель используя все 5+ миллионов паблик матчей без test split»)
- **Предшественник:** E-242 — та же цель, но про-корпус и 20 предматчевых
  признаков. Там вывод был «отдельная модель ничего не добавляет». Здесь другой
  дизайн, и вывод другой.

## 1. Популяция взята вызовом продовой функции, а не копией правил

`build_early_nw_public_dataset.py` импортирует `is_early_nw_match`
(`base/analise_database.py:999`) и зовёт её на каждом матче. Это не «те же
правила» — это ТА ЖЕ функция, поэтому модель обучена ровно на тех картах, что
попадают в словарь `early_dict`. Расхождению взяться неоткуда по построению.

| что | значение |
|---|---|
| частей корпуса | 82 |
| карт в популяции | **3 212 482** |
| доля радианта | 0.5339 |
| период | 24.03.2026 - 09.08.2026 |
| метка | сторона маркера (доминатор), **не** победа карты |

Признаки — только десять hero_id по позициям, порядок строит
`win_model_veto._heroes_vector` (radiant pos1-5, затем dire pos1-5). Ни живого
состояния, ни ELO, ни игроков: нетворт в early-схеме это ЦЕЛЬ, подавать его на
вход нельзя.

## 2. Обучение: боевой артефакт на всей популяции, метрики — на отложенном тесте

По запросу alex боевой артефакт зафичен на ВСЕХ 3 212 482 картах без отложенного
теста. Чтобы при этом знать цену строки, тот же скрипт отдельно обучает
honest-модель на train+val и меряет её на последних 20% по времени.

| | значение |
|---|---|
| C (выбран по валидации) | 0.003 |
| колонок | 16 764 |
| честный тест | 642 497 карт |
| **AUC** | **0.71584** |
| точность | 0.6585 |
| база «всегда одна сторона» | 0.5328 |
| log loss / brier | 0.616099 / 0.213862 |

**Край сетки проверен и снят.** C=0.003 стоял на границе `C_GRID`, и val_log_loss
падал монотонно в сторону меньших C — это выглядело как непройденная граница.
Замер за границей показал внутренний минимум:

| C | val_log_loss | val AUC |
|---|---|---|
| 0.0003 | 0.622629 | 0.707340 |
| 0.001 | 0.618131 | 0.712870 |
| **0.003** | **0.616361** | 0.714971 |
| 0.01 | 0.616398 | — |
| 0.03 | 0.616858 | — |
| 0.1 | 0.617284 | — |

## 3. Главное: существующая late-строка отвечает на этот вопрос НАОБОРОТ

Вопрос, решающий судьбу новой строки: не читается ли ранний перевес по уже
стоящей в панели late-строке? Обе модели драфтовые и принимают один и тот же
вектор из десяти hero_id, поэтому сравнение прямое — одна выборка, один вход.

Считает `early_nw_vs_late_headtohead.py`. Он берёт honest-модель, а не боевой
артефакт: боевой видел тестовые карты по построению и выиграл бы арифметикой.
Late-модель считается пакетом по тем же файлам, что грузит модуль; совпадение с
`late_win_model.radiant_probability` проверено на 500 картах, max|delta| = 4.99e-07.

| | значение |
|---|---|
| тестовых карт | 642 497 |
| early-NW AUC | **0.71584** |
| **late AUC на этой цели** | **0.48416** |
| корреляция оценок | **-0.0989** |
| сторона совпадает | 46.85% |
| расхождений | 341 461 |
| на расхождениях права early-NW | **65.93%** |
| на расхождениях права late | 34.07% |

**Механизм.** `late_win_model` обучена на картах `duration >= 36` на ПОБЕДУ КАРТЫ
(E-240). Состав, выигрывающий длинную игру, — это поздний скейл, и он ранний
перевес по нетворту как раз ОТДАЁТ. Поэтому знак получается обратный: чем
увереннее late-строка называет сторону, тем вероятнее ранний перевес возьмёт
ДРУГАЯ. Существующая строка не «молчит» про ранний перевес — она вводит в
заблуждение, если её так прочитать.

## 3а. По длине карты механизм виден прямо

| длина | карт | early-NW AUC | late AUC |
|---|---|---|---|
| < 28 мин | 93 415 | 0.7542 | 0.4609 |
| 28-40 мин | 343 523 | 0.6840 | 0.5378 |
| >= 40 мин | 205 559 | 0.7506 | **0.4049** |

U-образность у early-NW и провал у late в тех же двух краях. Читается так:
короткие карты предсказуемы, потому что сильный состав давит; длинные —
потому что поздний скейл предсказуемо отдаёт ранний темп; смешанная зона это
28-40. Late перевёрнута сильнее всего на 40'+, где цели ближе всего к
противоположным.

**Это НЕ согласуется с E-242**, где на про-корпусе 40'+ падали до AUC 0.6237.
Конструкции разные (паблик + только драфт против про + 20 предматчевых
признаков), так что прямого противоречия нет, но объяснения тоже нет.
**Гипотеза (не проверена):** на 40'+ сторона маркера антикоррелирует с
победителем карты. Проверка названа в разделе 6.

## 4. Калибровка: проценту в панели можно верить

Строка печатает процент, и он обязан что-то значить. Полосы считает
`early_nw_calibration.py` на тех же отложенных 642 497 картах honest-моделью.

| полоса | карт | доля | заявлено | факт | разрыв |
|---|---|---|---|---|---|
| 0.50-0.55 | 114 278 | 17.8% | 0.5249 | 0.5215 | -0.0034 |
| 0.55-0.60 | 111 709 | 17.4% | 0.5749 | 0.5775 | +0.0026 |
| 0.60-0.65 | 103 881 | 16.2% | 0.6247 | 0.6233 | -0.0014 |
| 0.65-0.70 | 94 047 | 14.6% | 0.6745 | 0.6749 | +0.0004 |
| 0.70-0.80 | 144 457 | 22.5% | 0.7462 | 0.7467 | +0.0005 |
| 0.80-0.90 | 66 972 | 10.4% | 0.8399 | 0.8402 | +0.0003 |
| 0.90-1.01 | 7 153 | 1.1% | 0.9190 | 0.9210 | +0.0020 |

Максимальный разрыв 0.0034. Перекалибровка НЕ нужна — в отличие от late-модели
(наклон 0.8187, E-240) и глобальной переуверенности ~15% (E-144). Средняя
уверенность 0.6586; выше 0.70 — 34.0% карт, выше 0.90 — 1.1%.

## 5. Проводка в прод

| файл | что |
|---|---|
| `base/early_nw_win_model.py` | загрузка артефакта, `radiant_probability` / `early_nw_index` / `verdict` / `panel_line`; молчаливый отказ, kill-switch `EARLY_NW_MODEL_ENABLED=0` |
| `base/win_model_veto.py` | `_LAST_FILL["early_nw"]`, `last_early_nw(index)`, блок расчёта в `_prematch_index` в try/except, поля `early_nw_side/confidence/error` в журнал оценок |
| `base/cyberscore_try.py` | строка `🕐 Early NW ML-модель: …` НАД `🕑 Late ML-модель` |
| `base/tests/test_early_nw_win_model.py` | 25 тестов, все зелёные |

**Отказ молчит по контракту:** нет артефакта, не встал sklearn, незнакомый герой
— `None`, и строка просто не печатается. Причина видна только в
`runtime/prematch_model_eval.jsonl` полем `early_nw_error` — иначе «модель
молчит» неотличимо от «модель работает» (см. память
`prematch-model-refusal-is-silent`).

**Гейт ставки не задет.** `_WIN_MODEL_PANEL_RE` ищет 🤖 (U+1F916); новая строка
несёт 🕐 (U+1F550), late — 🕑 (U+1F551). Проверено тестом, который достаёт оба
шаблона из исходника через `ast` и прогоняет их по двухстрочной панели.

**Артефакт `.joblib` в git не попадает** (`.gitignore:177`), поэтому на serv1 его
надо доставить отдельно — иначе прод молча не увидит модель и строки не будет.

## 6. Где искать ошибку в замере

- **Сравнение с late не «нечестно» — оно и есть вопрос.** Late-модель никто не
  учил на этой цели. Но в панели её число УЖЕ стоит, и вопрос ровно в том,
  можно ли по нему прочитать ранний перевес. Ответ: нельзя, и прочтение
  переворачивает знак.
- **С общей предматчевой моделью (🤖) сравнения НЕТ.** Она требует ELO-снимка и
  на паблик-корпусе не считается. E-242 на про-корпусе намеряла, что общая
  модель предсказывает маркер с AUC 0.7492, то есть НЕ ХУЖЕ специально
  обученной (0.7462). Поэтому прибавка новой строки НАД 🤖-строкой **не
  доказана**; доказана только над late-строкой.
- **Боевой артефакт зафичен на тесте** (запрос alex). Все числа этой записи
  получены honest-моделью на train+val. Боевой брать для метрик нельзя.
- **Проверка гипотезы из 3а:** добавить `didRadiantWin` в
  `build_early_nw_public_dataset.py`, пересобрать (~1 ч) и померить корреляцию
  стороны маркера с победителем карты по стратам длины. Если на 40'+ она
  отрицательна — механизм подтверждён.
- **Паблик -> про не бесплатен.** duration_over43 даёт 0.6010 на паблике против
  0.5866 на про. Числа этой записи паблик-овые; про-проверка не делалась.
