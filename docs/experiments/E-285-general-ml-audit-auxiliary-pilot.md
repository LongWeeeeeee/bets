# E-285 — общая предматчевая ML: обучение, покрытие и пилот дополнительных моделей

Дата: 12.09.2026. Задача: `ingame-gr3t`. Статус: аудит и ограниченный пилот завершены;
улучшение полной общей модели **не установлено**. Прод в этой задаче не изменялся.

## Что подтвердилось в общей модели

Общий прогноз считает `base/prematch_scorer.py:PrematchModel.score`, вызываемый
`base/win_model_veto.py:_prematch_index`. Это стандартизованная логистическая
регрессия с отдельными совместно обученными весами для доступных наборов данных.
Полная ветка содержит 35 признаков, `no_org` — 34, `no_account_no_org` — 7.
Источник разметки признаков и лестницы: `base/prematch_components.py`.

| Что покрывается | Признаки / механизм | Ограничение |
|---|---|---|
| Опыт игрока | `games`, `hero_games`, `pos_games`, `hero_pool` | Нужны известные аккаунты; это агрегаты, не полная последовательность карьеры |
| Сила и соперники | `elo`, `opp_elo`, `hybrid_strength` | Account-ELO и гибридный рейтинг ростера — разные источники |
| Форма и исполнение | `form`, IMP, относительные GPM/LH/KDA/урон/networth, EWMA | Статистика игроков может отсутствовать; это не измерение всех аспектов игры |
| Команда / состав | `hybrid_strength`, взаимодействия силы и опыта | Не доказано покрытие стабильности состава, коммуникации, смены патча и ролей |
| Очные | `h2h_resid`, разрешение организации по составу | Только когда найдена соответствующая история |
| Драфт | `draft_logit`, WR героев, matchup, lane, synergy, farm dependence | `wr30` здесь — статистика героев, не винрейт игрока |

Один нулевой или неизвестный аккаунт исключает весь account-блок. Ветка выбирается
по реально доступным ключам; это намеренная запасная модель, обученная без этих
колонок, а не заполнение всех неизвестных игроков средними значениями.

Строка пользователя «без статистики игроков и очных» соответствует
`no_account_no_org`: остаются `draft_logit`, `wr30`, `farm_dep`, `vs_wr`, `cp_lane`,
`syn_pos_mean`, `hybrid_strength`. Поэтому ELO и драфт в разложении есть, а
индивидуального опыта игроков и очных в этом конкретном расчёте нет. Наличие
`hybrid_strength` не означает наличие account-ELO: рейтинг ростера имеет отдельный источник.

Вклад `ELO +13%, драфт -87%` — нормированные по сумме абсолютных вкладов части
логита. Знак плюс означает Radiant, минус — Dire. Это не прибавка/убавка 13/87
процентных пунктов к вероятности. Перехват модели не представлен этими долями.
`57.6%` — уверенность модели; `54.1%` — значение исторической таблицы калибровки
ветки, а `1.85` — округлённое `1 / 0.541`. Различие этих чисел само по себе не ошибка.
Точный матч из примера не идентифицирован: ID/команды не предоставлены, точного
совпадения в проверенном журнале не найдено. Причину отсутствия конкретных аккаунтов
по одному тексту карточки установить нельзя.

## Что именно попробовали добавить

Полная общая ML на свежем периоде не пересчитана: у существующей 35-мерной матрицы
и hybrid-кэшей **нет пересечения** с cohort после 13.08. Для полноценного теста
нужно сначала восстановить согласованные по match_id исторические player/hero/h2h
и hybrid-признаки. Подставлять сегодняшний снимок в прошлые матчи нельзя.
См. также E-258: существующий replay использует start-time batching; для нового
запуска требуется проверка доступности исходов по завершению матча, а не только старту.

Выполнен ограниченный exploratory screening **поверх компонента All**, а не всей
35-мерной модели. Это отвечает только на вопрос о наличии дополнительного сигнала
в фазовых/laning/kills-прогнозах без контроля ELO и статистики игроков.

Входы: frozen `evaluation_model.joblib` для All/Early NW/Early Win/Late
из E-260; team-laning history-модель от 09.09; сохранённые `absolute` out-of-time
kills-прогнозы E-281. Для фаз намеренно взяты evaluation-версии, а не сегодняшние
full-fit веса, чтобы не обучаться на будущем относительно оцениваемых матчей.
Kills — исследовательская версия с безусловными целями side≥30 / total≥55;
это **не побитовое воспроизведение текущей панели с отсечённой серединой**.
Laning — командная NW10-модель, не три отдельные линии.

Из 687 карт kills-test после 20.08 исключены все 141 зарезервированные E-278 карты;
пересечение с public phase/laning обучающими корпусами — ноль. По оставшимся 546
сверены match_id, составы, герои и время; они охватывают 20 UTC-дней до 11.09.
Все источники и SHA закреплены в `pilot_preparation.json`.

Split по дням: обучение до 01.09, validation 01–06.09, test с 07.09.
Серии, пересекающие границы, удалены целиком; переходы дополнительно требуют
`end + 3600 < cutoff`. Итог: **409 / 95 / 40 карт**, test — 30 серий.
История laning фильтруется до query-time минус час. Public phase fit завершён до
периода оценки. LogisticRegression со StandardScaler: `C ∈ {0.01, 0.1, 1}`
выбирается только на validation отдельно для каждого рецепта, затем refit на
train+validation; test не используется для выбора C.

| Входы | AUC test | Log loss test ↓ | Accuracy test |
|---|---:|---:|---:|
| All как есть | 0.6000 | 0.68065 | 57.5% |
| All + обученная калибровка (контроль) | 0.6000 | 0.68450 | 50.0% |
| + Early NW | 0.6350 | **0.67044** | 60.0% |
| + Early Win | 0.6100 | 0.68040 | 62.5% |
| + Late | 0.6050 | 0.67962 | 62.5% |
| + Laning | 0.5975 | 0.68527 | 52.5% |
| + килы Radiant и Dire | 0.5725 | 0.70698 | 57.5% |
| + тотал килов | 0.5975 | 0.68439 | 52.5% |
| + все три фазы | 0.6375 | 0.67493 | 60.0% |
| + все дополнения | 0.5700 | 0.70875 | 57.5% |

Результат: наиболее интересен Early NW. Его paired delta log loss к обученному
контролю `−0.01407`, series-bootstrap 95% CI **[−0.03097; +0.00155]** — ноль
внутри интервала. Все восемь интервалов delta log loss включают ноль.
Выборка мала, рецептов девять, поправки на множественные сравнения нет, исторический
cohort уже рассматривался в других исследованиях. Даже лучший вариант не является
доказанным улучшением или основанием для деплоя. Калибровка контроля здесь хуже
сырого All; сравнение только accuracy с 50% скрывало бы этот факт.

## Где искать ошибку и следующий шаг

1. Не смешивать все тики с уникальными картами; арифметический replay требует
   совпадения SHA. Сам пример пользователя пока не локализован.
2. Проверять дату fit весов отдельно от даты snapshot таблиц. Историческая
   калибровка ветки не гарантирует текущий WR или доходность.
3. Перед full35-стеком восстановить признаки по match_id с end-time gate для всех
   источников; не соединять старые позиционные массивы с обновлённым compact.
4. Для нового стека получить именно serving-совместимые kills/laning прогнозы;
   разные цели и версии этого пилота нельзя выдать за полную проверку боевой панели.
5. Зафиксировать Early NW как кандидата для следующей проверки, но измерить его
   добавку к общей модели на свежем, ранее не использованном парном периоде.
   Не выбирать победителя и не менять пороги по этим 40 картам.

Прод-файлы, веса, конфигурация сервиса и runtime в этой задаче не менялись;
push/restart не выполнялись. Полный эксперимент общей модели остаётся открытым.
