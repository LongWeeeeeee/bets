# E-265 — повторный аудит и улучшение laning

## Вопрос и результаты аудита до нового обучения

Запрос alex: «перепроверь все может можно сделать лучше модель».
[E-264](E-264-laning-minute10.md) сохраняется как результат первой версии.
Её исходный test уже просмотрен; использовать его повторно как независимое
подтверждение улучшения нельзя. Цель остаётся пятизначным STRATZ-исходом каждой
линии на 10-й минуте, без подмены индивидуальным NW1000/1500.

Независимый аудит не нашёл ошибки topology или timestamp leakage. Проверены
строгий конец матча до запроса истории, направления Dire, purge и отсутствие
пересечения карт между train/validation/test. Остались два известных ограничения:
позиции назначены ретроспективно и фактическое время поступления результатов
не сохранено. Предматчевое применение требует корректно известных позиций.

Найдены возможности улучшения: обе модели v1 дошли до лимита 300 деревьев с
улучшающейся validation loss; fit использовал только 400k из 4.01m train-карт;
в признаках отсутствовал остальной драфт и недавняя история отдельно от всей.
Исправлен дефект API: нечисловые, NaN/Inf и дробные hero IDs больше не проходят
молча. Значения целых ID нормализуются в один формат. Для новых metadata неизвестный
feature set отклоняется, чтобы не применять неправильную схему признаков.

## Зафиксированный до запуска протокол

Ровно два кандидата плюс сохранённая v1 как допустимый победитель:

| Вариант | Train-карт | Признаки | Доступность истории | Fit |
|---|---:|---|---|---|
| v1 | 400 000 | lane-драфт + all-time player/role/hero | end < start | существующие 300 деревьев |
| longer | 400 000 | те же признаки | end < start | до 900 деревьев |
| context_recent | 800 000 | lane-драфт, все 10 героев, all-time + 30 дней, own-minus-opponent history | end + 1 час < start | до 900 деревьев |

Оба новых fit: CatBoost MultiClass depth6, lr0.08, seed42, четыре потока,
stop после 60 итераций без улучшения validation. Широкая сетка не запускается.
`context_recent` — пакет изменений: его эффект нельзя приписывать только объёму,
контексту или recency без отдельного ablation. Верхний лимит fit не обещает
полного насыщения модели, если validation продолжит улучшаться на последнем шаге.

Границы временных частей сохраняются из E264: 13 июля / 13 августа UTC с purge
по завершению карты. Валидация — те же 100k карт; старый её прогноз воспроизводится
до нового fit. Среди будущих eligible-карт исключены все 100k ID теста E264,
затем детерминированно зарезервированы 100k других ID. Хеши исходного manifest,
базового отчёта, кода признаков/треннера и выбранных IDs сохраняются в plan.json
до формирования новых моделей. Три линии каждого матча всегда вместе.

Свежих локальных JSON после 04.09.2026 не обнаружено. Confirmation состоит из
ранее не использованных ID **того же исторического периода**, поэтому он не
является новым временным или prospective тестом и не доказывает перенос на pro.
История в будущем периоде обновляется только завершёнными доступными матчами;
параметры модели остаются фиксированными, текущий исход в историю не входит.

Победитель выбирается только по raw validation log loss из трёх вариантов.
Затем только на validation подбирается один temperature в [0.6,1.6], а
selection.json и калиброванный артефакт записываются **до** метрик confirmation.
Применение temperature воспроизводится при загрузке сохранённой модели.
Улучшение подтверждается, если верхняя граница 95% дневного paired-bootstrap
интервала loss(candidate − v1) < 0. После просмотра confirmation новый подбор
конфигураций не продолжается. Результаты остальных кандидатов показываются
для прозрачности, но не меняют зафиксированный выбор.

## Проверки и диагностические контроли

- Признаки v1 пересчитываются и побитно сопоставляются с сохранёнными строками
  на пересечении, в том числе train/validation. Сохранённая v1 должна повторить
  прежнюю validation loss с точностью 1e-10.
- На validation у v1 подставляется история с задержкой 15 и 60 минут. Это
  sensitivity к доступности результатов; реальные ingestion timestamps неизвестны.
- История v1 перемешивается между матчами внутри дня с сохранением блоков
  всех 10 игроков. Потеря качества показывает зависимость от соответствия
  истории игрокам; это не самостоятельное доказательство отсутствия leakage,
  поскольку перемешивание нарушает также связь player-hero.
- Calibration: multiclass Brier (сумма по пяти классам), top-label ECE и ECE
  каждого класса по десяти равным bins, до/после temperature.
- Направление среди фактически решённых линий отчётливо отделено от всех линий.
  Top10/25/50/100% сравниваются на равном числе линий, tie считается ошибкой.
- Paired bootstrap — 2000 выборок календарных дней; внутри дня сохраняются
  все карты и три линии каждой карты. Отдельные интервалы для easy/mid/hard.
- Реальный выбранный артефакт после загрузки должен повторить прогнозы на
  64 confirmation-картах до 1e-12; IDs confirmation не пересекаются с test E264.
- Regression suite проверяет окна, задержку, нижнюю/верхнюю границы, дробные
  timestamps, отсутствие влияния будущих исходов, schema metadata, temperature,
  невалидные значения hero IDs и полный маленький v1→v2 run.

Независимый raw audit: 18 непустых player-slot (по 6 train/validation/
confirmation), 216 значений `hc` сверены прямой агрегацией исходного корпуса
без вызова `build_history`. Max abs error 1.73e-7 (float32). Проверены account,
роль на обеих сторонах, hero, lane/Dire-sign, строгая верхняя и включённая
нижняя границы. Также подтверждены индексы/ID/timestamps, purge, размеры
800k/100k/100k и нулевое пересечение confirmation с test E264.
Сводка: `runtime/artifacts/laning/20260908_stratz_v2/independent_history_audit.json`.

## Где искать ошибку

1. `partition_v2`: исключение старых test IDs, одинаковая validation, strict
   completion purge, вложенность 400k в 800k и outcome-independent sampling.
2. `prior_history`: разные dtype timestamps не должны усекать дробную границу;
   lower inclusive / upper strict; нулевой account не накапливает историю.
3. `build_history`: recent-окно отсчитывается от `start − delay`, то есть при
   часовом lag оно покрывает завершения возрастом от часа до 30 дней + часа.
4. `lane_features`: own-side история, Dire-sign, все 10 героев в R1..5,D1..5;
   тип признака определяется по dtype, числовые разности не становятся category.
5. `run`: параметры/temperature выбираются до confirmation, текущие labels
   не попадают в history, cache не принимается при несовпадении plan/ID/labels.
6. `LaningModel.load`: feature metadata и temperature соответствуют артефакту;
   v1 без metadata остаётся совместимой и не получает расширенные признаки.
7. Улучшение public не равно pro readiness; корректные positions и фактическая
   задержка результатов остаются требованиями к будущей serving-интеграции.

## Результат

Оба fit завершились (`DONE`, shell exit 0). Первый занял 24m19s, второй
53m29s; весь прогон с подготовкой истории — около 85 минут на четырёх потоках.
Оба достигли 900 деревьев, best iteration 899. На validation:
v1 **1.312155**, longer **1.308526**, context_recent **1.303569**.
Выбран `context_recent`, temperature **0.988530204**; после калибровки
validation loss **1.303545**. Выбор записан до confirmation.

а не более поздний временной holdout. Все варианты ниже оценены на одних IDs.

### Финальная проверка и артефакт

- Повторный расчёт loss, accuracy3, conditional accuracy/AUC, top10 и Brier
  напрямую из сохранённых probabilities совпал с summary до 1e-12 для всех
  четырёх вариантов, без вызова training `metrics`.
- Независимый дневной bootstrap 5000 draws, seed266 дал CI
  **[−0.00944394, −0.00843149]** и тот же вывод. Основным остаётся заранее
  заданный bootstrap2000/seed265, новая проверка не меняла выбор.
- Загрузка CBM проверена на первых 64 картах в trainer и на ещё 64 случайных
  контрольных картах отдельно: max delta **0.0**. Metadata задаёт delay3600 и
  window2592000. SHA кода совпали с исходным plan; selection создан до predictions.
- 23 regression-теста корпуса, истории, API, partition и маленького полного
  v1→v2 run прошли; после финальной metadata-правки отдельно повторены 11 тестов
  модели и 4 теста improvement. Shell syntax, py_compile и diff check прошли.
- Сводка отдельной проверки:
  `runtime/artifacts/laning/20260908_stratz_v2/independent_artifact_audit.json`.
- Выбранная модель: `data/laning_models/20260908_stratz_v2/selected/history.cbm`.
  Для загрузки: `LaningModel.load(directory, with_history=True)`; для истории
  использовать `build_history(..., **model.history_config)`.

Улучшение умеренное и подтверждено в этом public confirmation. Оно не доказывает
перенос на pro или применимость к порогам NW1000/1500. Расширенный вариант
обучен на 800k карт, не на всех 6.69m; full refit не выполнялся. Оба fit ещё
улучшались на пределе 900 деревьев, поэтому глобального оптимума не заявляем.
После просмотра confirmation дополнительных вариантов не подбирали.
Production не переключался; E264 и его артефакты сохранены.
