# E-325. Производственная прематч-панель + kills-v3 team/player фичи

- **Дата:** 2026-09-23. Вопрос владельца: улучшают ли v3 T/P-фичи боевые прематч-модели
  килов самой панели (окна w_5_15 / w_10_20 / w_15_25 / w_20_30, rad_30_25, total_55_50).
- **Продолжает:** [E-318](E-318-kills-v3-prematch-vs-panel.md) (v3 не бьёт панель кроме
  total55; следующий рычаг — нести фичи v3 в корпус панели, а не наоборот).
- **Рабочее имя при пререгистрации:** E-319 (номера E-319..E-324 заняты другими сессиями;
  реальный номер — E-325).

## 1. Пререгистрированный дизайн (до любых тестовых метрик)

- **A:** панельные колонки (928, из них 122 приора) на od3-покрытых строках трейна (185 562).
- **B:** A + od3 orient-0 T+P блоки (152 колонки), те же строки, те же параметры CatBoost
  (3000 it, lr 0,03, depth 6, l2 6, es 150, seed 20260814), тот же seed.
- **Тест:** панельный тест 26 016 карт (TEST_FROM 1774742400).
- **Первичная метрика:** LL, обрезанный [1e-3, 1-1e-3]; со-первичная — dAUC.
- **Статистика:** парный day-бутстрэп, 2000 реплик, seed 0, 136 дней
  (`cluster start//86400`), по каждой из 6 целей отдельно.
- **Вторичное:** B против продовых артефактов (.cbm, учились на 456k).
- **Предсказание:** side/total dLL −0,005…−0,015; окна −0,001…−0,005.
- **Критерий опровержения:** B−A > −0,002 на всех целях.
- **Конфаунд под контролем:** missingness/эпоха — через сравнение A против B на том же
  подмножестве строк.

## 2. Верификация: два REJECT и фиксы

- **REJECT #1 (устаревшие кэши 482k):** источники `ideas_batch{1,2,5,5b}` выросли до
  1 260 895 строк против панельных 482 486; `catalog_features.npz` отсутствовал
  (-> только 122 приорные колонки); LL-клип 1e-15 на изотонических 0/1 стоил ~0,0013.
  Фикс: выравнивание всех панельных входов по mids к корпусу 482 486 (тест ровно 26 016);
  гейты: cols == prod feature_names, prod35 AUC ~0,685 на 26 016; первичный LL обрезан
  [1e-3, 1-1e-3] (пререгистрировано); инкрементальные записи.
- **REJECT #2 (семантика каталога):** пересобранный каталог отличался по ЗНАЧЕНИЯМ F6/F7/F8
  от того, на чём училась прод-панель (причина — изменение CausalPrior 2026-09-19:
  start-order -> end-time availability, pre-test population means -> fixed 36/0;
  детали — `runtime/artifacts/kills/panel_plus_v3/catalog_prod/semantics.md`).
  Доказательства: F7_p_tot_kills_mean_sum у прода границы 96–142 (медиана 123) против
  пересборки q05/q50/q95 11,5/64,6/110; прод .cbm AUC на входах харнесса total 0,680
  (док 0,7439), rad 0,678 (док 0,7330). Полный прогон ОСТАНОВЛЕН до завершения целей.
  Фикс: восстановлена прод-семантика каталога
  (`catalog_features_prod.py` -> `catalog_prod/`, 43 с) + жёсткий гейт: прод .cbm AUC
  на A-тесте харнесса в пределах 0,005 от `build_panel_models.md` по каждой цели.
- **Жёсткий гейт ПРОЙДЕН:** прод .cbm AUC на A-тесте = .678394/.670490/.659027/.641201/
  .733042/.743895 против дока .6784/.6705/.6590/.6412/.7330/.7439 (все < 0,00005).
- **Гейт порядка строк:** row-order AUC 0,685191 (док ~0,685), PASS
  (`runtime/artifacts/kills/panel_plus_v3/row_order.log`).

- B лучше A на 5/6 значимо по LL и на 6/6 по AUC (w_20_30: LL незначим, AUC значим).
- B бьёт прод по поинту на всех 6 целях, несмотря на обучение только на 40% трейна.
- **Прод не менялся.** Развёртывание любого изменения панели — решением владельца.

## 6. Конфаунды и ограничения

- **Старые start-order приоры, возможно, оптимистичны** [гипотеза, не проверено]:
  приор мог видеть исходы карт, стартовавших, но не закончившихся до запроса, — офлайн-AUC
  панели слегка завышены; это делает B−A консервативным.
- **A училась на 40% подмножестве** (od3-покрытые 185 562 из 456 470) — абсолютные уровни
  A ниже продовых; валидно только парное B−A, а не A против прода.
- **Прод .cbm собран 20.08 против дока 16.08** — расхождение дат сборки/модели; гейт по AUC
  (< 0,00005) закрывает его для сравнения.
- **Множественность:** 6 целей без поправки; первичен LL, dAUC со-первичен.

## 8. Где искать ошибку

- **LL-клип:** первичен клип [1e-3, 1-1e-3]; клип 1e-15 на изотонических 0/1 стоит ~0,0013 LL —
  при пересчёте не смешивать (`ll` против `ll_raw` в metrics.json).
- **Семантика каталога:** F6/F7/F8 обязаны быть start-order + pre-test population mean
  (прод-семантика августа); end-time availability даёт другие ЗНАЧЕНИЯ и роняет прод-AUC
  до ~0,68 — сверка через жёсткий гейт прод .cbm AUC перед прогоном.
- **Выравнивание по mids:** все панельные входы выравниваются по mids корпуса 482 486;
  без этого тест ≠ 26 016 (позиционные кэши против растущего корпуса).
- **Порядок строк:** row-order AUC обязан быть ~0,685; отклонение — признак перестановки.
- **nice:** run.py отказывает при nice < 10 (run.py:192).
