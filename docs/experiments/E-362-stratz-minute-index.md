# E-362. Какой минуте соответствует индекс в рядах STRATZ

**Вопрос (карточка ingame-4aba, находка E-357).** Живой NW в момент `game_time = t` совпадает с рядом
`pro_corpus_rich.npz`, интерполированным в точке `t/60 + 1` (MAE 563), а не `t/60` (MAE 1 225; 64 наблюдения,
`runtime/experiments/misc/pl_late_nw_index_check.py`). Два объяснения: (а) индекс `k` = состояние на `k:00`,
а живые часы отстают на ~60 с; (б) индекс 0 — отсчёт до горна, индекс `k` = состояние на `(k−1):00`.
Решение, которое меняется: сдвигать ли живой вход минутной модели E-347 и все офлайн-анализы, сравнивающие
живое состояние на m-й минуте с `nw[m]`.

**Предсказание до прогона.** Если верно (б), убийство в первые 60 с после горна проявится скачком |xp|/|nw| в
индексе 2, а не 1, и XP-лид в индексе 1 будет нулём почти всегда (до смерти первых крипов опыта нет ни у кого).

## Данные и команда

```
venv_catboost/bin/python3 runtime/experiments/misc/stratz_minute_index_check.py \
  > runtime/artifacts/misc/stratz_minute_index_20261008/out.txt
```

Карты с длительностью ≥ 900 с и рядом XP: 303 999. Убийство в момент `fb` сразу добавляет опыт и золото, так что
первый индекс со скачком = первый отсчёт после `fb`.

## Результат

|---|---:|---:|---:|---:|---:|
| [−90, 0) — до горна | 67 444 | 96,2 % | 446 | 526 | 587 |
| [0, 30) | 46 526 | 19,5 % | 65 | **342** | 400 |
| [30, 60) | 22 668 | 10,6 % | 50 | **353** | 388 |
| [60, 90) | 29 096 | 10,7 % | 65 | 187 | **408** |
| [90, 120) | 37 559 | 10,9 % | 65 | 186 | **438** |
| [120, 180) | 50 354 | 10,6 % | 65 | 186 | 259 |
| [300, 600) | 9 950 | 10,2 % | 75 | 184 | 256 |

- xp[0] = 0 у 99,9 % карт, xp[1] = 0 у 69 %, xp[2] = 0 у 0,9 %.
- Последний индекс, где NW меняется, = floor(длительность/60) + 1 у 100 % карт 15–38 мин: последний отсчёт —
  на последней целой минуте, а не «конец карты».
- Накопительные килы: первый индекс с rk+dk ≥ 1 = ceil(fb/60) у 98,0 % (ещё 1,6 % на единицу позже) —
  `rk[j]` = убийства до `j:00`, по верным часам (совпадает с журналом `.omc/decisions.md:742`).

**Механизм.** Верно (б): ряды STRATZ `radiantNetworthLeads` / `radiantExperienceLeads` начинаются отсчётом до
горна, `nw[j]` = состояние на `(j−1):00`. Живые часы не отстают — объяснение (а) не нужно. В одном npz
`nw[j+1]` и `rk[j]` описывают один момент `j:00`.

**Правило для анализов:** живое состояние на `m:00` = `nw[m+1]` = `xp[m+1]` = `rk[m]`/`dk[m]`.

## Решение

Правило индексации записано (этот документ, память агента). Минутную модель E-347 переобучить на `nw[m+1]`
при следующей пересборке — карточка ingame-4aba остаётся открытой с этим шагом. Ставок сдвиг не меняет: ни одно
боевое правило ставки не берёт порог из `nw[m]` офлайн без живой проверки.

## Где искать ошибку

- Ряд NW в npz протягивается после конца карты; для «последнего индекса» брались только карты ≤ 38 мин.
- Ненулевой xp[1] у ~10 % карт без ранней крови: отсчёт «на 0:00» берётся с точностью до тика, а опыт может
  прийти от нейтралов/рун до горна — на вывод не влияет (скачок от убийства 50–65 → 342–353).
- first_blood в npz — секунды игрового времени STRATZ (отрицательные = до горна); если поле окажется в другой
  шкале, таблица сдвинется целиком, но не изменит, в каком индексе виден скачок относительно соседних окон.
