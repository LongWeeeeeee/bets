# E-28. Починка прод-политики kills: харнесс занижал прод на 4.4 п.п.
- **Дата:** 2026-08-06
- **В чём был дефект.** Прод (`_kills_window_policy_combo`) берёт окно с
  МАКСИМАЛЬНЫМ `|ed|` среди прошедших свой `min_ed`, ждёт полосу именно этого
  окна и **не имеет фолбэка** — полосы более слабых окон пропускаются со
  статусом `not_strongest_window`. Харнесс брал ПЕРВОЕ сработавшее по времени и
  при провале NW-гейта переходил к следующему окну.
- **Харнесс:** `runtime/experiments/kills/kills_policy_fixed.py` (обе политики
  рядом, чтобы разницу можно было пересчитать в любой момент)
- **Размер расхождения** (дамп rel0, 1 099 tier-1 про-карт):

  | правило | ставок | WR | ROI@1.8 |
  |---|---|---|---|
  | первое по времени (старое) | 627 | 72.7% | +30.9% |
  | **сильнейшее окно (прод)** | **428** | **77.1%** | **+38.8%** |

  Харнесс ставил на 199 карт больше при WR на 4.4 п.п. ниже — это ставки,
  которых прод никогда бы не сделал. То есть все прошлые «прод-отборные» числа
  ЗАНИЖАЛИ реальный прод, а не завышали.
- **Что перепроверено на исправленной политике:**
  * **E-07 (зеркальный пулинг) — вердикт устоял и стал чище.** Раньше нужен был
    контроль на равном объёме, теперь пулинг проигрывает прямо: 353 ставки при
    76.5% против 428 при 77.1% — меньше и объёма, и качества.
  * **E-10 (гейт по плотности словаря) — вердикт устоял.** Кривая плоская:
    0 -> 77.1%, 30k -> 77.9%, 50k -> 77.6%, 75k -> 76.2% при падении объёма до
    38%. Пик +0.8 п.п. внутри CI. Харнесс `games_gate_fixed.py`.
- **Что НЕ перепроверено:** E-11 (чистый 1v1 против 1v1+with) — требует
  пересчёта `ed` под другую слоевую политику, то есть повторной экстракции.
  `lt_star` и все замеры по star-блокам (E-02, E-09, E-18) дефекта не касались:
  они идут не через kills-политику.
- **Где искать ошибку:** (1) NW-гейт в харнессе проверяется на дедлайне окна
  (`nw_t_{минута-1}`), а прод опрашивает всю полосу — это аппроксимация
  «последним моментом полосы»; (2) `required_sign` (ранний kills-поток задаёт
  сторону от early star) в харнессе не моделируется — там сторона всегда из
  знака `ed`.
