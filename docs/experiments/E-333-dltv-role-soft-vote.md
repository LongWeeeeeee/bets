# E-333. Роль игрока из DLTV в разрешении позиций sourcetv-пробы

- **Дата:** 2026-09-24. Жалоба alex на сигнал «СТАВКА НА Team GPK x1» (Team GPK vs Team Daxak,
  BetBoom Streamers Battle 15, карта 9013821098): «на dltv io pos1, ancient apparition pos 5 как
  и должно быть у нас наоборот». В панели у Daxak было pos1 Dragon Knight, pos2 Ancient
  Apparition, pos5 Io, варнинг «conf=0.63, совпало с историей 2/5».
- **Вопрос:** чем заполнять слоты игроков без про-истории, когда перестановочный резолвер
  `base/sourcetv_probe.py:_resolve_positions` берёт их только из `base/hero_position_stats.json`.
  Популяция — стороны журнала, ушедшие в перебор; стороны с полной историей (method=raw) не
  затрагиваются.
- **Разбор инцидента:** в журнале serv1 история в про-индексе есть у 2 из 5 (Dark Willow → 4,
  Bristleback → 3, обе совпали); DK/Io/AA без истории получили DK1 (P=0.407), AA2 (P=0.032),
  Io5 (P=0.702). Ростер DLTV (страница команды через Camoufox и JSON-поиск): Io=1, DK=2, BB=3,
  DW=4, AA=5; фарм из live-json DLTV на 23-й минуте (Io 217 добиваний, AA 12) подтверждает.
  Статистика героя Io на pos1 не поставит никогда — нужны данные об игроке.
  `~/.config/dota_probe/position_overrides.json` (заполняется `base/scrape_dltv_positions.py`)
  на serv1 отсутствует, локальный — от 10.06 и этих игроков не содержит.
- **Источник:** `GET https://dltv.org/api/v1/search?q=<account_id>` — открытый JSON без
  JS-проверки (страницы команд её требуют); поиск нечёткий, брать только игрока с
  `steam_id == account_id`, поле `role` 1..5. С serv1 — 200 за 0.6 с.
- **Харнесс:** `runtime/experiments/draft-cp/dltv_roles_20260924/` — `dltv_roles_eval.py`
  (роли DLTV по аккаунтам окна), `truth.py` (истина Stratz), `compare.py` (жёсткие правила A/B),
  `dig.py` (разбивка по P(герой на позиции) и матрица ошибок DLTV), `soft.py` (сетка весов),
  `control.py` (знаковый тест, половины по времени). Окно зафиксировано `now=1790255750`.
- **Артефакты:** `runtime/artifacts/draft-cp/dltv_roles_20260924/` — входы
  `pos_resolution.jsonl`, `truth.json`, `dltv_roles.json`; выводы `compare.txt`, `dig.txt`,
  `soft_pinned.txt`, `control.txt`.
- **Запуск:** `venv_catboost/bin/python3 runtime/experiments/draft-cp/dltv_roles_20260924/soft.py`
  (`truth.py` — тем же python из корня репо; `dltv_roles_eval.py` ходит в сеть, остальные — нет).
- **Прогноз до замера:** роль DLTV на слотах без истории верна в ~85%, жёсткая замена поднимет их
  точность с ~55% до ~75%. **Не подтвердился:** текущая точность там уже 78.6%, DLTV — 75.8%.
- **Дефекты, найденные ДО выводов:** первая копия харнесса обрезала `; recent=...` комментарием
  при закреплении окна (NameError) — исправлено, вывод закреплённой копии побайтно равен исходному.
- **Результат** (342 стороны, 1 710 слотов):

  | правило | сторон верно целиком | слоты без истории (299) | «история игрока» (843) | «история команды» (568) |
  |---|---|---|---|---|
  | сейчас (только статистика героя) | 274 | 0.786 | 0.909 | 0.974 |
  | A: роль DLTV = raw (вес 1.0) без истории | 272 | 0.756 | 0.918 | 0.974 |
  | B: DLTV выше истории по всем командам | 271 | 0.759 | 0.912 | 0.977 |
  | мягкий голос w=0.2, только без истории | 277 | 0.816 | 0.909 | 0.974 |
  | **мягкий голос w=0.2, все игроки с ролью** | **283** | **0.829** | **0.918** | **0.979** |
  | мягкий голос w=0.3, все игроки | 284 | 0.809 | 0.922 | 0.982 |

  Разбивка слотов без истории по P(герой на назначенной позиции): P<0.15 — текущий 0.381
  (n=21), DLTV 0.786 (n=14); P≥0.4 — текущий 0.864 (n=213), DLTV 0.762 (n=164). Матрица DLTV→истина
  там же: роль 1 верна 16/16, роль 5 — 78/89 (11 раз на деле pos4), роль 2 — 34/54 (14 раз pos4),
  роль 4 — 33/48. Инцидент при w=0.2: DK2+Io1+AA5 = 0.950 + 0.6 = 1.550 против DK1+Io5+AA2 = 1.141.
- **Контроль:** w=0.2 против текущего по сторонам: лучше 16, хуже 7 (односторонний знаковый
  p=0.047); неделя 1 — 9/4, неделя 2 — 7/3. Изменённые стороны приходятся на 11 команд, итог по
  командам [−3, −1, 0, 0, 1, 1, 1, 2, 2, 2, 4]. Стороны method=raw при переборе с голосом не
  меняются (0/342), поэтому ветку raw не трогаем и DLTV там не запрашиваем.
- **Где искать ошибку:** (1) истина — вывод Stratz, а не протокол; (2) роли DLTV запрошены 24.09 и
  применены к картам до 14 дней назад — дрейф ростера; если DLTV выводит роли из тех же недавних
  матчей, на истории это частично in-sample; (3) эффективная выборка мала: 25 игроков без истории,
  изменения в 11 командах — p≈0.05 держится на нескольких командах; (4) вес выбран по сетке из 8
  значений на тех же 342 сторонах, защита — плато 0.15–0.3 и одинаковый знак в обеих неделях;
  (5) истина есть только для 171 из 337 карт (про-лиги Stratz), турниры стримеров вроде
  инцидентного в неё почти не попадают — там игроков без истории больше.
- **Вывод:** внедрено в `_resolve_positions` как голос w в переборе
  (`base/dltv_player_roles.py`, env `DLTV_ROLE_WEIGHT`=0.2, `DLTV_ROLE_LOOKUP=0` — откат,
  кэш `runtime/dltv_player_roles_cache.json`). Формула conf и поля raw_known/raw_matched не
  менялись (история), в журнал добавлены `dltv_known`/`dltv_matched` и поле слота `dltv` —
  по ним через 1–2 недели пересчитать точность на живых сторонах тем же `control.py`.
