# E-286 — общая модель с причинной историей и добавкой Early NW

Продолжение E-285 по запросу пользователя «делай». Задача `ingame-gr3t`.
Цель — сравнить полную общую модель и ту же модель с Early NW на одинаковых
картах. Результат пилота All+EarlyNW не доказывает пользу сверх опыта игроков,
силы состава и остальных признаков общей модели.

## Данные и причинность

`base/prematch_history_replay.py:CausalPrematchHistory` потребляет завершённые
матчи в порядке `(end, match_id)` и передаёт таблицы истории существующему
`PrematchModel.score`. Формулы признаков берутся из существующего scorer;
коэффициенты модели при привязке истории не меняются. В production helper
не подключён. Данные используют OpenDota hero IDs и порядок позиций 1–5 по сторонам.

Результат допускается только при `end < query_start`; равенство исключается.
Отдельно сохраняется часовой embargo на границах train/validation/test.
`end = start + duration`: фактическое время публикации API в архиве отсутствует,
поэтому end-time причинность не доказывает доступность записи в эту же секунду.

Аккаунтный Elo и глобальные нормы обновляются по всему допустимому корпусу;
подробные счётчики игроков — только для аккаунтов целевого cohort. Строки с
частично неизвестными аккаунтами сохраняют глобальную статистику героев и нормы,
но нулевые аккаунты не получают историю. WR30 обрезается при каждом результате,
поэтому редкие запросы не приводят к накоплению всей карьеры в очереди.
Очные организаций используют отдельный обычный K24 рейтинг, независимо от
org Glicko; сохраняются все позиции игрока для существующего position guard.
Query привязывает только нужные ключи matchup/synergy, без полного обхода таблиц.

Гибридный ELO восстанавливается полным `ELO.replay.replay_events` по замороженным
307 raw-файлам и девяти изменённым файлам хвоста. SHA исходников и данных включены
в manifest. Старый `finished.npz` не используется: в нём нет match_id и нельзя
доказать соответствие строк только метаданными. Старый snapshot также не используется:
изменённый хвост содержит карты до его reference time. Дубликаты с различным
содержимым останавливают сборку, пропущенный ELO исключает карту.

Полная rich-история сверяется с cohort по match_id, времени, исходу, героям и
аккаунтам. Модель вызывается с историческими team IDs. Нехватка account-признаков
исключает карту одинаково из всех вариантов; только отсутствующий `h2h_resid`
нейтрализуется нулём по контракту no_org. Покрытие и причины исключений сохраняются.

## Зафиксированное сравнение

Кандидат — единственный дополнительный сигнал Early NW, выбранный в E-285.
All уже является входом общей модели. Используются те же evaluation-прогнозы
All/EarlyNW и те же 546 карт, с SHA-привязкой к завершённому E-285. Reserved 141
не используются. Другие фазы, laning и kills повторно здесь не отбираются.

Четыре варианта:

1. Вероятность замороженной общей модели с обученной логистической калибровкой.
2. Та же вероятность + Early NW.
3. Refit всех 35 признаков.
4. Refit тех же 35 признаков + Early NW — основная парная проверка.

Сырые прогнозы замороженной общей модели приводятся описательно. Для refit
`StandardScaler + LogisticRegression`, `C ∈ {0.01, 0.1, 1}`, выбор по validation
log loss, затем refit на train+validation. Границы прежние: validation с 01.09,
test с 07.09; пересекающие границы серии удаляются целиком. Обе пары оцениваются
по общим картам; доверительный интервал строится bootstrap по сериям.

Это **историческая диагностика**: test уже изучался, подбор кандидата использовал
E-285. Нельзя считать эти карты новым независимым подтверждением. Также нельзя
считать причинный архив полной копией исторического serving: часть исходных
данных и curated tier priors не имеет исторической даты публикации.

## Результаты и ограничения

ELO: 1 395 625 уникальных raw-карт после объединения, неизвестных end-time нет;
до последнего query обработано 1 395 623 результата. Рейтинг получен для всех
546 целей. ELO-этап занял 314.6 s.

Истории: 1 261 115 завершённых rich-строк, invalid 0; этап занял 423.9 s.
Полные account-признаки доступны для **492 / 546 (90.1%)** карт: 359 `full`,
133 `no_org` с явно нейтральным h2h. Исключены 49 карт с нехваткой прошлой
истории хотя бы одного аккаунта и 5 с конфликтом разметки позиций. У всех 49
account IDs положительны: наличие ID само по себе не гарантирует наличие истории.
Ни данные, ни position guard не подменялись ради покрытия.

После общей eligibility и прежнего split: **365 / 88 / 38**, test — **28 серий**.
Не сравнивать эти метрики напрямую с E-285 на 40 картах: здесь другая общая маска.

| Вариант | C по validation | AUC test | Log loss test ↓ | Brier ↓ | Accuracy |
|---|---:|---:|---:|---:|---:|
| Замороженные веса общей модели, без калибровки | — | 0.60665 | 0.69384 | 0.24521 | 55.3% |
| Вероятность тех же весов + обученная калибровка | 1 | 0.60665 | 0.70003 | 0.24705 | 50.0% |
| Та же вероятность + Early NW | 1 | 0.60388 | 0.70468 | 0.24938 | 50.0% |
| Refit всех 35 признаков | 0.1 | **0.77839** | **0.57285** | **0.19632** | **68.4%** |
| Refit 35 + Early NW | 0.1 | 0.77562 | 0.57590 | 0.19768 | 68.4% |

Основная парная разница `+NW − full35`: **+0.0030448 log loss**,
series-bootstrap 95% CI **[−0.0005394; +0.0065973]**. Добавка к калиброванной
вероятности старых весов: **+0.0046415**, CI **[−0.0011493; +0.0105891]**.
Обе точечные оценки хуже, оба интервала включают ноль; оснований включать Early NW
в общую модель этот опыт не дал. На validation Early NW также хуже full35
для каждого из трёх проверенных C. Все веса, выбор C и predictions сохранены.

Переобучение 35 признаков выглядит существенно полезнее добавки Early NW на
этом периоде. Это не доказательство будущего качества: 38 ранее рассмотренных
карт, маленький train и отличия архивных историй от serving не позволяют
утверждать, что найден готовый production replacement или доказано недообучение
старой модели. Сырые старые веса здесь применены к причинной реконструкции и
фиксированному evaluation All, а не к полному историческому serving snapshot.

### Независимая проверка результата

`check_general_ml_full35.py` повторно посчитал все пять наборов метрик, сверил
ID/исходы/маски, disjoint серии, строгий completion embargo, нулевое пересечение
с reserved 141 и SHA receipt. Результат **PASS**:
`runtime/artifacts/misc/general_ml_audit_20260912/full35_independent_checks.json`.

В stderr исходного fit были RuntimeWarning `divide by zero / overflow / invalid`
из NumPy matmul. Конечность прогнозов недостаточна, поэтому дополнительно выполнен
`check_general_ml_full35_numerics.py`: прямое поэлементное вычисление логитов и
независимый L-BFGS fit той же логистической цели без матричного умножения, с
RuntimeWarning как ошибками. Это проверка чисел, не новый подбор рецептов.

Получены те же четыре выбора C; replay сохранённых прогнозов отличается максимум
на **1.11e-16**. Более строгий независимый optimizer отличается по вероятности
не более **0.000695**, по log loss не более **0.000119**. Его парные delta также
положительны: +0.002938 и +0.004551. Проверка **PASS**, вывод об отсутствии выигрыша
сохранился. Первопричина предупреждений библиотеки не установлена; они не скрыты
и сохранены в исходном stderr. Отчёт — `full35_numerical_checks.json` в каталоге аудита.

Это планируемый нижний объём, не доказательство достаточной статистической мощности.

## Где искать ошибку и следующий шаг

- Сверять ID и содержимое raw/rich/cohort, а не только длины массивов.
- Проверять `latest_end < query_start` и не использовать текущие таблицы
  игроков или ELO snapshot ретроспективно.
- Проверять причины потери покрытия и одинаковые маски обеих моделей.
- Отдельно оценивать refit35 и замороженные веса: это разные контролируемые вопросы.
- Пересчитать метрики из сохранённых прогнозов и проверить SHA receipt после job.
- Для независимого подтверждения нужны новые pro-карты после фиксации финальных
  весов; первоначальный протокол намечает минимум 500 карт / 200 серий, единственный
  финальный тест, CI95 верхняя граница delta log loss < 0 и Brier не хуже.
  Это новый план проверки, не уже выполненный gate. Его начало следует связать
  с SHA реально обученного кандидата. Периодический heartbeat не создавался.

Никаких изменений production весов, service configuration, push или restart
эта задача не выполняет.
