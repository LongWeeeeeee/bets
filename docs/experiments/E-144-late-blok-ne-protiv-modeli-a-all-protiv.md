# E-144. Против модели играет All-блок, а не Late

## Вопрос

alex: «блоки late/all всё ещё несут информацию против нашей ML-модели». Пример —
карта, где модель дала Radiant 99.9%, а Late и All указывали на соперника:
фаворит вёл 14k на 32-й минуте, отдал лид, карту проиграл.

Проверяемое утверждение: **знак блока объясняет остаток модели `y - p`**. Если
модель уже всё знает, знак блока не должен ничего добавлять.

## Данные и метод

* про-корпуса `runtime/pro_pool_merged_metrics.json` (6 028) +
  `pro_maps_metrics_rebuild_20260801.json` + `pro_both_early_full.json`, слияние
  по `id` → 6 188 карт с `late_output` (28-60 мин) и `post_lane_output`
  (драфт-часть блока All);
* leak-free предматчевые вероятности —
  `runtime/artifacts/misc/map_winner_live_new_prior_forward/causal_prematch_oof.npz`
  (`prior_asof < map_timestamp`), колонки `current` (production Hybrid, E-137)
  и `e99`. Пересечение с корпусами — **3 768 карт**, AUC prior на них 0.7645;
* звёздные хиты считаются ровно как в проде: `data/star_thresholds_by_wr.json`
  на WR60 плюс белый список `_STAR_SIGNAL_METRICS`. Для Late это
  cp1vs1 >= 2 / cp1vs2 >= 2 / solo >= 2, для All — cp1vs1 >= 4 / cp1vs2 >= 3;
* `late_rel` / `all_rel` — нетто-хиты со знаком относительно СТОРОНЫ МОДЕЛИ
  (отрицательное = блок против модели).

**Оговорка о модели.** Прод считает `data/prematch_model_artifact_v3.npz`
(29 признаков, AUC 0.7140), здесь взят causal OOF родственной модели E-137/E-99.
Артефакт v3 — снимок с гейтом свежести 3 дня, историю им не пересчитать, поэтому
проверка идёт на двух ближайших родственниках, и оба дают один результат.

## Результат 1. Late на минуте 0 — ноль

| проверка | значение |
|---|---|
| регрессия `y ~ logit(p) + late_hits`, prior current | z = **-0.49** |
| то же на prior E-99 | z = **-0.52** |
| непрерывная шкала `late_sum` | z = **-0.24** |
| индекс >= 8: late ПРОТИВ (n=1 296) | факт 74.1%, ждали 76.5% |
| индекс >= 8: late ЗА (n=1 261) | факт 73.3%, ждали 75.8% |
| разница (против − за) | **+0.002, 95% ДИ [-0.030, +0.034]** |

Крайняя ячейка ровно как в примере — все три звёздные late-метрики против
модели (`late_rel = -3`, n=502): ждали 76.7%, факт 75.3%, разница -1.4 п.п.
Симметричная ячейка «все три ЗА» (n=495) дала -3.3 п.п., то есть **хуже**.

## Результат 2. Почему ноль — фаворит закрывает раньше

Late предсказывает не «кто выиграет», а «как». Индекс >= 8:

| late относительно модели | доля карт 28+ мин | WR на картах <28 мин | WR на картах 28+ мин |
|---|---:|---|---|
| ПРОТИВ (n=1 296) | 0.749 | **96.9%** при ожидании 85.2% (+11.7) | **66.4%** при ожидании 73.5% (-7.1) |
| нейтрален (n=355) | 0.808 | 88.2% (+6.2) | 71.4% (-3.4) |
| ЗА (n=1 261) | 0.836 | 84.1% (+1.0) | 71.2% (-3.3) |

Против скейлящегося драфта фаворит либо закрывает карту рано (и делает это
почти без осечек), либо попадает в зону, где его перевес тает. Сумма двух
режимов и даёт ровно ноль на минуте 0.

## Результат 3. Информацию против модели несёт All-блок

| проверка | значение |
|---|---|
| регрессия `y ~ logit(p) + all_hits`, prior current | z = **+3.26** |
| то же на prior E-99 | z = **+3.13** |
| совместно с late: `all_hits` / `late_hits` | z = **+3.90** / -2.22 |
| непрерывная шкала `all_sum` | z = **+2.67** (совместно +3.32) |
| корреляция `all_hits` с `logit(p)` | **0.055** |

Ячейки при индексе >= 8 монотонны по силе блока:

| `all_rel` | n | ждали | факт | разница |
|---:|---:|---:|---:|---:|
| -2 | 242 | 0.759 | 0.678 | **-8.1 п.п.** |
| -1 | 509 | 0.768 | 0.715 | -5.3 п.п. |
| 0 | 1 203 | 0.760 | 0.750 | -1.0 п.п. |
| +1 | 636 | 0.760 | 0.734 | -2.6 п.п. |
| +2 | 322 | 0.762 | 0.783 | +2.1 п.п. |

**Главный эффект: all против − all за = -5.2 п.п., 95% ДИ по series-bootstrap
[-9.4, -1.1]** (2 086 кластеров, n = 751 / 958). По полосам уверенности:

| полоса p | all ПРОТИВ | all ЗА |
|---|---|---|
| 0.58-0.80 | -6.2 п.п. (n=461) | -0.1 п.п. (n=610) |
| 0.80-0.90 | **-10.1 п.п.** (n=152) | -4.3 п.п. (n=187) |
| 0.90+ | -2.0 п.п. (n=138) | -0.7 п.п. (n=161) |

Таблица 2×2 показывает, что вклад целиком у All: «late против × all ЗА»
(n=211) даёт **+0.8 п.п.**, а «late против × all против» (n=535) — **-6.8 п.п.**

В поток это попадает часто: **25.8%** карт с индексом >= 8 (751 из 2 912) идут
с All-блоком против модели.

## Результат 4. После 30-й минуты Late решает всё

Карты, где сработала ставка модели (индекс >= 8) и известно состояние на 30-й
минуте (2 128 из 2 912). Лид считается со стороны модели:

| состояние на 30' | база WR | late ПРОТИВ | late ЗА |
|---|---:|---|---|
| модель отстаёт > 2k | 26.4% | **18.0%** (n=211) | 30.8% (n=305) |
| равно (\|лид\| < 2k) | 53.0% | **34.1%** (n=91) | **66.9%** (n=127) |
| модель ведёт 2-6k | 77.8% | **64.9%** (n=111) | 87.8% (n=139) |
| модель ведёт > 6k | 93.9% | 91.4% (n=475) | 97.3% (n=401) |

Предматчевое ожидание во всех ячейках одинаковое (0.71-0.78), то есть модель
эти группы не различает вообще. Случай из вопроса — переход из «> 6k» в «равно»
на 32-й минуте при late -3: эмпирический винрейт такой позиции **34%**, а не
82% (и не 99.9%).

Это тот же вывод, что в [E-33](E-33-late-ne-sloman-ego-merili-i-primenyayut-ne-na-to.md):
late работает на своей популяции (равная игра после 28-30'), а прод снимает
сигнал там, где и без него 85%+. Здесь добавлено, что то же верно **внутри
популяции ставки по модели**.

## Что с «99.9%»

Число в сообщении — сырая `probability`. Ставка считается не по ней:
`lan_expected_wr` заморожен на **0.8207 при любой уверенности >= 83%**
(`LAN_ODDS_GRID`, min_odds 1.22). То есть прод уже дисконтирует 99.9% до 82%.
Калибровка prior по полосам: в 0.70-0.90 модель завышает на 4-5 п.п., в
0.95-0.99 расхождения нет (-0.1 п.п.), при p >= 0.99 — 80 карт из 80.

## Состояние прода

`win_model_veto.model_bet` (serv1, `/root/main`) гейтится **только** по
|индекс| >= 8; в docstring `_try_dispatch_prematch_model_bet` прямо написано:
«Звёзды, нетворс, линии и тир команд не спрашиваются». Блоки на ставку модели
не влияют никак — направление вето обратное (модель ветует блоки, не наоборот).

## Ограничения

* prior — родственник прод-модели, не она сама (см. оговорку выше);
* популяция — про-карты пула после 2026-04-01, а прод-калибровка 70.0% снята на
  2 456 LAN-картах; перенос порога на LAN не проверялся;
* разрезы по длительности и состоянию на 30' условны на пост-фактум величине —
  это описание живого решения, а не предматчевый фильтр.
