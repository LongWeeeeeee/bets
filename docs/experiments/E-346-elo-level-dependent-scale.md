# E-346. Разница ELO на разных уровнях рейтинга

- **Запрос владельца (02.10.2026):** «мы считаем elo diff, однако elo diff 300 на рейтинге 1500 и 1200 например и 2800 и 2500
  это разные вещи и такое мы не учитываем».
- **Что оценивается:** боевой вариант A (`new3x_dur_ac`, в проде с 25.09, E-338) и для сравнения K24. Рейтинг стороны —
  среднее рейтингов пяти аккаунтов. Уровень карты L = (r_a + r_b) / 2. Вероятность p = 1 / (1 + 10^(−Δ/400)).
- **Теория:** в классическом Elo сдвиг всех рейтингов на константу ничего не меняет. 1500 — лишь стартовая точка; поэтому
  `init1450` в E-335 был «пустышкой по построению». Вопрос эмпирический: работает ли шкала 400 одинаково на всех уровнях
  в наших данных.

## Пререгистрация (до первого прогона, docstring `level_eval.py`)

- **Гипотеза:** наклон логистической связи «исход ~ Δ» зависит от уровня L.
- **Опровержение:** поправка по уровню, подобранная на BACK, не лучше общей поправки на картах вне подбора: 95 % ДИ разницы
  log loss накрывает 0, а наклоны по квинтилям уровня перекрываются.
- **Решение:** если подтвердится — вероятность ELO (процент в сообщении, пороги 70 % / 58,5 %) и/или правило обновления
  получают поправку по уровню. Если нет — ответ владельцу числом.
- **Конфаунд:** уровень коррелирует с опытом (новые аккаунты стартуют с 1500, рейтинг ещё не сошёлся), с тир-списками и с
  эпохой. Контроль — член опыта (M3), M4 = уровень + опыт, сетка «уровень × опыт».
- **Прогноз:** TEST Δ log loss (M2 − M1) в [−0,002; 0]. В верхнем квинтиле наклон ниже (E-336: T1 против T1 фаворит
  переобещан на +0,02…+0,04). Точность меняется меньше чем на 0,1 п.п. (симметричное перешкалирование не меняет фаворита).
- **Модели** (логистическая регрессия, обучение на BACK; x = Δ·ln10/400 — логит боевой вероятности,
  z — стандартизованный L, u — стандартизованный log(1 + gmin)):
  - M1: a + b·x;
  - M2: + c·x·z + e·x·z²;
  - M3: M1 + f·x·u;
  - M4: M2 + f·x·u.
  - gmin — меньшее из двух средних чисел сыгранных карт по пяти аккаунтам стороны.

**Механизм.**
- **Опыт держится в обоих периодах.** У новичков рейтинг ещё не разошёлся от стартовых 1500, и разрыв занижен. У ветеранов
  рейтинг копит старую историю и переоценивает разрыв.
- **Уровень при фиксированном опыте** даёт наклон ближе к 1, а не дальше (TEST: ветераны 0,80 → 0,85 → 0,92).
- **Перекос верхнего квинтиля в 2024–25 — эффект ветеранов:** медиана gmin там 537 карт против 19–124 в остальных.
  На этой же идее построен «ускоренный K для новичков» в варианте A, а неопределённость рейтинга уже мерили через Glicko:
  E-170 +0,0013, E-229 — ноль на отборе ставок.

## Где искать ошибку

1. **Первый прогон** считался только на картах, сопоставленных с `pro_corpus_rich` (`hit`, TEST 20 610). Результат сохранён
   в `level_eval_run1_hit_only.json`, выводы те же. Основной прогон — на всех лиговых картах, как «all» в E-338.
2. **gmin** — число событий реплея (лиговые карты с 2012 г.) на аккаунт до запроса, а не стаж в годах.
3. **Маска бота** использует нынешние `id_to_names` + overlay (`robust_eval.bot_mask`). Для BACK/SEL это отбор по будущему.
4. **Границы квинтилей и терцилей** взяты с BACK. Уровень дрейфует по эпохам: медиана L на BACK 1580, на TEST 1572; 90-й процентиль 2104 против 1866.
5. **Предупреждения sklearn** (matmul overflow на macOS Accelerate) подавлены. Коэффициенты M2/M4 проверены на конечность
   (assert в `level_eval.py`).
