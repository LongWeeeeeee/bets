# E-210. Ингейм-отчёты Stratz — три идеи, три нуля

- **Дата:** 2026-08-17 (alex: «давай ингейм отчёты»)
- **Что собиралось:** `heroDamageReport` (урон по типам, длительность станов,
  дизейблов и замедлений в обе стороны) и `abilityCastReport` (по каждой
  способности и каждой цели: количество применений, урон, длительность).

## 1. Сбор: найден батч, которого «не было»

В `maps_research.py` было записано «один матч = один запрос». Две формы там
проверены верно (`matches(ids:)` закрыт, playback внутри `teams -> matches` не
влезает), но **алиасы GraphQL не пробовались**:
`query { m0: match(id: X){...} m1: match(id: Y){...} }`. У них нет множителя
списка, стоимости просто складываются.

Замер: **8 матчей проходят, 9 дают сложность 310 914 при лимите 300 000**, то
есть один матч стоит около 34 546. На живом сборе — ровно 8.0 карт на запрос,
ошибок ноль: **15 440 карт за 1 416 запросов** вместо 15 440.

Цена прежней ошибки: сбор playback стоил 23 887 запросов вместо примерно 3 000.

## 2. Чего в данных нет

`duration` в `abilityCastReport.targets` пуст у **всех 2 275 507** записей
способность×цель. Парная матрица контроля («A вешает на B N секунд стана»)
не строится — не потому что мешает конструкция, а потому что данных нет.
Поле в схеме есть, значений в нём нет.

## 3. Что измерено (тест 3 847 карт, сплит по времени)

| состав | AUC | прирост к cp1vs1 |
|---|---|---|
| только cp1vs1 | 0.5606 | — |
| **cp1vs1 + парный урон (эталон E-206)** | **0.5656** | **+0.0050** |
| cp1vs1 + применения способностей | 0.5597 | −0.0009 |
| cp1vs1 + урон способностей | 0.5627 | +0.0021 |
| cp1vs1 + урон + применения | 0.5639 | +0.0032 |
| cp1vs1 + стан (длительность) | 0.5584 | −0.0023 |
| cp1vs1 + замедление | 0.5607 | +0.0001 |
| cp1vs1 + дизейбл | 0.5606 | +0.0000 |
| cp1vs1 + магический урон | 0.5585 | −0.0021 |
| cp1vs1 + физический урон | 0.5608 | +0.0001 |
| cp1vs1 + весь контроль | 0.5582 | −0.0025 |
| cp1vs1 + урон + весь контроль | 0.5638 | +0.0031 |

Две строки решают дело: применения **поверх урона** дают 0.5639 против 0.5656 у
одного урона, контроль поверх урона — 0.5638. Обе величины не просто бесполезны,
а мешают.

В одиночку применения дают AUC **0.4858** — ниже монетки.

## 4. Данные посчитаны верно, сигнала нет

Проверка вменяемости: больше всего стана накладывают Slardar (16 914 единиц
длительности за карту), Wraith King, Enigma, Dark Willow, Earthshaker, Lion,
Shadow Shaman, Nyx Assassin. Список ровно тот, что ожидаешь. То есть меряется
именно контроль, просто он не предсказывает.

Догадка про применения, не проверенная: у одного игрока попалась способность с
`count 2046` — спам-абилка или аура. Такие записи забивают счётчик, и
«применение» меряет частоту, а не намерение. Фильтр по редким способностям
не пробовался.

## 5. Правило, которое из этого следует

Контроль на уровне героя — это почти константа героя (Slardar всегда много
станит). А база уже обусловлена на состав: cp1vs1 знает, какие герои в драфте, и
их среднюю силу. Поэтому любая величина, зависящая ТОЛЬКО от героя, добавить не
может — она уже внутри.

Это объясняет всю серию разом: синергия (E-208, +0.0002), ассисты (E-207, ноль),
контроль и типы урона (здесь) — все они функции состава. Единственное, что
добавляло, — **парный остаток**: сколько урона A наносит именно B сверх того,
что следует из силы A и уязвимости B (E-206, +0.0098).

Отсюда практический вывод для будущих идей: спрашивать не «есть ли такая
колонка», а «даёт ли она ПАРНУЮ величину, которой нет в силе героев по
отдельности». Если нет — считать необязательно.
