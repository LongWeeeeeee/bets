# E-281. Относительные профили героев и их команд

Запрос: обучить модели ≥ килов карты и стороны на пабликах, использовать
нетворс, опыт, убийства и смерти героя отдельно от команды с ним; абсолютный
уровень паблик-килов не переносить на про. Допускается дообучение на про.

## Подтверждённые дефекты и ограничения прежнего пути

- `build_panel_models.build_targets`: ≥55 против ≤50 и ≥30 против ≤25.
  Промежуточные значения исключены; это условные вероятности, а не обычные
  вероятности превышения порога на всех картах.
- Та же функция обучает только Radiant; комментарий признаёт отсутствие
  зеркального обучения общей модели стороны.
- `causal_priors.PRIOR_NAMES` содержит командные килы, NW/XP, но не deaths.
- Cached `window_features_v2.parse` подставляет нули при пропущенной статистике
  и требует наличия хотя бы одного окна. Для новой цели итоговых килов raw
  извлекается заново без фильтра по наличию поминутного разбора.
- В пабликах нет постоянной организации. Команда с героем означает сторону
  конкретной карты; отдельная история team ID возможна только на про.

## Замороженный план проверки

Паблики до 01.06.2026; новые признаки хранят личные доли K/D/A/NW/XPM/GPM,
отношения к темпу всей карты, командные доли и участие в убийствах. Смерти
команды вычисляются по смертям её игроков, а не подменяются киллами соперника.
Пропуск остаётся NaN; нулевой знаменатель не означает нулевой показатель.
Герои упорядочены по стороне и позиции; ID разрежены, верхней границы 130 нет.

Про-обучение: июнь-июль; валидация: 01-19 августа; тест: с 20 августа.
Разделение по завершению матча; серия не должна пересекать train/val/test.
Гиперпараметры выбираются только на валидации, затем тест читается один раз.
Общий target стороны обучается в двух ориентациях, обе остаются в одном split.
Основные цели включают всю середину: total≥55 и side≥30. Сравнение с прежними
крайними целями приводится отдельно, без смешивания популяций.

## Воспроизведение

```sh
/Users/alex/Documents/ingame/venv_catboost/bin/python3 -m pytest base/tests/test_kills_relative_profiles.py -q
/Users/alex/Documents/ingame/venv_catboost/bin/python3 .orchestra/runtime/orchestra.py resources preflight --plan runtime/artifacts/kills/relative_transfer/extract_plan.json
/Users/alex/Documents/ingame/venv_catboost/bin/python3 .orchestra/runtime/orchestra.py resources run --plan runtime/artifacts/kills/relative_transfer/extract_plan.json --background
```

Планы включают SHA-256 исходников и raw-файлов. Каждый файл извлечения имеет
контрольную точку; повторный запуск проверяет SHA и использует готовый результат.
Результаты обучений, exact run IDs и проверки будут дописаны после завершения.
Production runtime и активные артефакты панели не изменяются этим экспериментом.

## Где искать ошибку

1. Утечка будущих пабликов в более ранний pro test; cutoff применяется к end.
2. Нули вместо отсутствующих K/D/NW/XP, включая старые кэши и знаменатели долей.
3. Самозасев справочника на своих train-строках; справочник должен быть раньше.
4. Различие суммы личных килов и официального scoreboard: текущая панель тоже
   использует player kills; это явно фиксируется как определение label.
5. Смешение разных порогов/выборок, матчей одной серии и двух ориентаций.
6. Новый scorer без прежних сильных блоков нельзя выдавать за улучшение всей
   текущей панели только по сравнению со слабым baseline.
