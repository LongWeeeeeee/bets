# E-264 — модель исхода лейнинга

## Вопрос и выбор маркера

Запрос: предматчевый прогноз лейнинга до 10:00, с учётом позиций, матчапов и
истории игроков. Разница NW 1000–1500+ предложена как ощутимое преимущество.

Проверка источника `bets_data/analise_pub_matches/json_parts_split_from_object`
показала: `radiantNetworthLeads` — командный ряд; `players[].networth` — итоговое
скалярное значение. Индивидуальных рядов NW нет. Поэтому нельзя восстановить
разницу суммы NW участников отдельной линии в 10:00, а итоговый NW нельзя
использовать ни как её подмену, ни как предматчевый признак.

Выбран разрешённый пользователем доступный маркер STRATZ: пять классов
`DIRE_STOMP, DIRE_VICTORY, TIE, RADIANT_VICTORY, RADIANT_STOMP`. Их вероятности
также суммируются в `Dire / tie / Radiant`. STRATZ-классы **не объявляются
эквивалентом** фиксированных порогов золота. E-80/E-86 предсказывали командный NW
через словарь линий; они не были проверкой индивидуального NW каждой линии.

В [официальном описании STRATZ](https://github.com/STRATZ-Esports/knowledge-base/issues/39)
указано: LaneScore измеряется на 10-й минуте обычной карты (Turbo — на 7-й),
объединяет нормированные NW, XP, CS и KDA и использует границы по линии/рангу.
Поэтому это более широкий маркер качества лейнинга, чем разница золота.
Текущий public collector `proceed_get_maps_with_data` в `base/maps_research.py`
запрашивает `gameModeIds: [22]`, bracket `[7,8]`. Сам компактный архив не хранит
gameMode; историческую неизменность этого фильтра каждая raw-строка не доказывает.

| Выход (перспектива Radiant) | Исход STRATZ | Radiant | Dire |
|---|---|---|---|
| easy | bottomLaneOutcome | pos1 + pos5 | pos3 + pos4 |
| mid | midLaneOutcome | pos2 | pos2 |
| hard | topLaneOutcome | pos3 + pos4 | pos1 + pos5 |

Командный NW source-index `[10]` при порогах 1000/1500 оставлен только как
дополнительная диагностика суммы прогнозов линий. Это существующая конвенция
проекта, не независимая проверка минутного offset STRATZ и не gold-target линии.

## Гипотеза, опровержение, решение

Гипотеза: прошлые результаты конкретного игрока на позиции/герое добавляют
информацию сверх матчапов героев. Она опровергается отсутствием улучшения
log loss на том же будущем тесте; незначимый дневной bootstrap не доказывает
устойчивый прирост. Решение: выбирать между draft-only и draft+history только
по validation log loss, затем показать результат обоих на запечатанном тесте.

## Протокол, зафиксированный до запуска

- Весь публичный архив сканируется; строгие позиции 1–5 каждой стороны,
  десять разных героев, валидные ID/время/длительность >=600 секунд.
- Пропуск NW не исключает STRATZ-матч. Нет/неизвестный lane label = -1;
  для общего сравнения используются матчи с тремя известными label.
- Идентичные ID оставляются один раз, конфликтующие исключаются целиком.
  Отсутствующий/invalid/sentinel account = 0; повторяющийся положительный account
  внутри карты исключает её. Исходники хешируются; запись атомарная.
- Границы 60/20/20 определяются по времени начала всего корпуса, одинаковые
  timestamps не разделяются. Из обучения удаляются карты, не окончившиеся до
  начала validation, из validation — до начала test.
- Независимая от исхода детерминированная подвыборка: максимум 400000 train,
  100000 validation, 100000 test **матчей**. Три линии карты всегда вместе.
  Это ограничение стоимости nonlinear fit, а не заявление об обучении на 100%.
- История вычисляется по всему валидному архиву, только из матчей с
  `startDateTime + durationSeconds < predicted_start`. В том числе допускаются
  ранее завершившиеся карты внутри test, как при последовательном применении.
  Параметры модели при этом не обновляются. Задержка поступления архива неизвестна.
- По игроку на позиции и по игроку на том же герое/позиции: средний ordinal
  score [-2,2], средний знак score, `log1p(count)`. Средние сглажены prior=10
  с нулевым центром. Для Dire знак исхода инвертируется. Account ID не является
  категориальным признаком модели; неизвестный игрок получает нулевую историю.
- Общая модель трёх линий: lane type, четыре героя core/support обеих сторон,
  две союзные и четыре вражеские пары. На mid support=0. Второй вариант добавляет
  историю четырёх участников. Используются установленные CatBoost/pandas/numpy;
  новый model framework и внешние зависимости не добавляются.
- Два CatBoost MultiClass fit, depth6, до 300 итераций, lr0.08, seed42,
  четыре потока; early stopping40 на validation. Финальный refit по test не делается.
  В stdout CatBoost поле `test:` означает переданный `eval_set`, то есть validation;
  финальный test используется для итогового отчёта отдельно.
- Оценка: пять/три класса, loss, accuracy, направление среди фактически решённых
  линий отдельно; top10/25/50/100% по уверенности **включает tie как ошибку**
  при предсказании победителя. Парный bootstrap блоками дней держит линии карты вместе.
- Артефакт после сохранения повторно загружается; его прогноз на реальных
  heldout-строках должен совпасть до 1e-12.

## Где искать ошибку и ограничения

1. Перепутанная перспектива: `LANE_SLOTS`, `PLAYER_LANES`, STRATZ bottom/mid/top,
   Dire-sign в `build_history`. Тесты проверяют эту границу.
2. Утечка: `prior_history` (строго `end < start`), `splits` (purge), сравнение
   реального start против фактического получения результата. Нельзя добавлять
   final player stats или текущую lane label в признаки.
3. Позиции в архиве присвоены после игры; в реальном предматчевом применении
   нужны корректно известные предполагаемые позиции. Смена линии и roam не
   реконструируются из данного среза.
4. Подмена target: gold threshold относится только к командной диагностике,
   score STRATZ нельзя трактовать как число золота. Для NW-маркера каждой линии
   нужен отдельный сбор индивидуальных timeline с точным временем 600 секунд.
5. Метрики: условная accuracy решённых линий не равна accuracy всех линий;
   сравнивать baseline/model на одних ID и равном покрытии.
6. Данные и кэш: source/code fingerprints, NaN-aware duplicate compare,
   source counts, positive duplicate account filter и пропуски histories.
7. Это публичный временной тест. Перенос на pro, калибровка боевого отбора и
   прибыльность здесь не проверяются. Production не подключается этим harness.

## Результат

Сборка завершена: 6 692 272 карты из 99 шардов; 9 925 записей исключены из-за
невалидных позиций, дубликатов и конфликтующих ID не найдено. Отдельно пропущены
два файла метаданных. Независимая сверка 75 записей из начала, середины и конца
архива подтвердила совпадение героев, STRATZ-исходов и командного NW с raw.

Границы временных частей: 13.07.2026 02:27:12 UTC и 13.08.2026 02:13:04 UTC.
После purge по окончанию доступны 4 014 516 / 1 337 738 / 1 338 455 карт;
на границах исключены 1 563 ещё не завершившиеся карты. Обучение использует
400 000 карт (1 200 000 линий), validation и test — по 100 000 карт
(300 000 линий). История использует весь валидный корпус с причинным cutoff.

Независимый прямой scan корпуса для 16 player/role-примеров из heldout подтвердил
все шесть history-признаков: максимальное расхождение 1.87e-7 (округление float32).
Проверены own-side знак, строгий `end < start`, count/log-count и hero-specific
история; разбиение на части и purge сверены с фактическими selected rows.
Проверки сохранены в `runtime/artifacts/laning/20260908_stratz_v1/`:
`raw_verification.json` и `history_verification.json`.

Оба fit завершены по 300 деревьев. По validation выбран `history.cbm`:
loss 1.312155 против 1.337613 у `draft.cbm`. Будущий test: 13.08.2026
02:13:29 UTC — 04.09.2026 00:06:09 UTC, 23 календарных дня с наблюдениями.

| Вариант | Log loss, 5 классов ↓ | Accuracy, 5 классов | Accuracy, 3 класса | Направление без tie | AUC без tie |
|---|---:|---:|---:|---:|---:|
| Частоты каждой линии из train | 1.405239 | 33.18% | 40.28% | 54.85% | 0.55765 |
| Только драфт | 1.327418 | 40.19% | 49.26% | 67.03% | 0.73439 |
| Драфт + история | **1.303250** | **41.58%** | **51.01%** | **69.32%** | **0.76311** |

`Направление без tie` и соответствующий AUC считаются на 220 298 фактически
решённых линиях, поэтому не являются точностью отбора на всех линиях.
Остальные колонки — все 300 000 линий. Распределение пяти классов:
16 459 / 89 739 / 79 702 / 95 149 / 18 951 в заявленном порядке Dire→Radiant.
У frequency baseline AUC каждой отдельной линии 0.5; pooled AUC выше 0.5
из-за различий частот между типами линий.

| Линия Radiant | Draft: направление без tie | History: направление без tie | History AUC без tie | History: accuracy 3 класса |
|---|---:|---:|---:|---:|
| easy | 67.29% | 68.83% | 0.74351 | 51.54% |
| mid | 68.24% | 71.90% | 0.79398 | 51.65% |
| hard | 65.60% | 67.34% | 0.73682 | 49.84% |

Парная разница loss `history − draft` = **−0.024169**, bootstrap по дням,
1000 выборок: 95% CI **[−0.025094; −0.023199]**. Прирост есть на всех трёх
линиях, сильнее всего на mid. Это интервал внутри проверенного временного
отрезка, не гарантия для другого патча/популяции. Ненулевую account-role историю
имеют 97.44% player slots теста; hero-specific история может отсутствовать.

При выборе победителя по уверенности, **считая tie ошибкой**:

| Покрытие всех линий | Число | Фактическая точность | Средняя вероятность модели |
|---|---:|---:|---:|
| 10% | 30 000 | 75.44% | 74.73% |
| 25% | 75 000 | 67.88% | 67.83% |
| 50% | 150 000 | 60.53% | 60.65% |
| 100% | 300 000 | 50.90% | 50.97% |

Это ранжирование на тесте с заранее выбранными долями, а не настроенные
пороговые гейты. Точность 50.90% отличается от 51.01% выше: здесь предсказывается
только победитель, а в трёхклассовой метрике можно предсказать ничью.

Дополнительная командная NW-диагностика для суммы ожидаемых lane score:
при `abs(teamNW[10]) >=1000` направление верно в 69.25% из 64 325 карт;
при `>=1500` — 72.26% из 48 854. Это условные командные результаты,
они не измеряют способность предсказать gold-margin отдельной линии.

Проверки: 14 regression tests PASS, в том числе полный маленький trainer run,
границы времени/overlap, перспектива Dire, topology, пропуски, дедупликация,
инвалидация кэша при изменении импортированного валидатора. Независимый
арифметический пересчёт по сохранённым predictions всех 300 000 линий подтвердил
loss и accuracy; повторная загрузка обеих моделей на 64 случайных heldout-картах
дала **max delta = 0**. `model_verification.json` и воспроизводящий скрипт
`verify_saved_models.py` сохранены рядом с остальными проверками.

После завершения добавлены тела импортированных parser/validator helpers в
cache fingerprint. Правила отбора, данные, признаки и веса не менялись;
повторный fit не требовался. `summary.json` содержит SHA исходников фактического
запуска до этого усиления invalidation, а `model_verification.json` подтверждает
их совпадение на момент проверки.

Итоговые модели: `data/laning_models/20260908_stratz_v1/history.cbm` (выбрана)
и `draft.cbm` (вариант без истории). Полный машинный отчёт — `summary.json`.
Production не подключён, restart/push не выполнялись. Доказан прирост на public
temporal holdout; перенос на pro и per-lane NW1000/1500 остаются отдельными задачами.
