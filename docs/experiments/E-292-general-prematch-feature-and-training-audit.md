# E-292. Аудит общей prematch ML

Запрос пользователя: перепроверить обучение, набор и формирование признаков;
проверить, каких признаков не хватает и какие избыточны. Исходный пример —
Rostikfacekid Club / Stray Club, карта 8999400918. Минус вклада draft при All
Radiant 51.62% объясняется центрированием и не доказывает ошибку модели.

## Подтверждено

1. **Актуальные веса.** Все 13 извлечённых массивов схемы, весов, ветвей и
   нормировок prod совпадают с E-287 candidate. На 57 первых карточках после
   установки, имеющих точный исход, replay записанных признаков дал max
   probability error **0.0**. Это проверка применения весов, не правильности
   происхождения каждого входа. Полный production snapshot не копировался.
2. **Схема и обучение.** 35 признаков; нет констант среди 15 205 train-строк.
   StandardScaler-параметры считаются по train; целевая переменная — победа
   Radiant; train `end+3600 < cutoff`, пересекающие границу серии исключаются.
   Формулы истории E-287 вычисляются существующим scorer, порядок берётся из
   `feature_names`. При прочитанном объёме явного расхождения шкал не найдено.
3. **Недостаточная проверка качества.** E-287 test — 38 ранее изученных карт,
   28 серий. Старые таблицы confidence→WR сохранены после замены full/no_org
   весов; manifest явно отмечает `UNVALIDATED_AFTER_WEIGHT_CHANGE`.
   Отображаемый historical WR и рассчитанный из него порог коэффициента нельзя
   считать заново подтверждёнными для текущих весов и текущей популяции.
4. **Время живого журнала.** После установки найдено 59 первых schema-2 записей
   с `game_time<=0`; для 57 найден точный outcome. Все 57 записаны ПОСЛЕ
   `outcome.start`, задержка **91.23–977.77 секунды**. Ноль строгих предматчевых
   записей по `prediction.ts < outcome.start`. Snapshot был до начала во всех
   57 случаях. Причина расхождения broadcast clock/API start отдельно не
   установлена. Метрики качества на этих строках в этом аудите не считались.
5. **Верхняя граница live delta отсутствует.**
   `base/prematch_live_delta.py:289` принимает только аккаунты и snapshot time;
   проверка в цикле — лишь `map.end > snapshot_ts`. Нет query cutoff и
   исключения текущего match_id. `base/prematch_scorer.py:1114` передаёт только
   snapshot timestamp. В локальном воспроизводителе на одной реальной карте
   запрос на момент её начала получил `games=1`, хотя as-of значение равно 0.
   Приращение касается `games`, `hero_games`, `pos_games` и производных
   взаимодействий; это не непосредственная подстановка результата победителя.
   **Фактическое загрязнение конкретной исторической карточки не доказано**:
   отсутствуют сохранённые версии live delta на каждый момент прогноза.

## Кандидаты на избыточность

Корреляции на E-287 train (не на test):

| Пара | Pearson r |
|---|---:|
| imp30 / imp50 | 0.9496 |
| hybrid_strength / elo | 0.9253 |
| imp_rel_pos / imp50 | 0.9084 |
| hero_pool / games | 0.9059 |

Корреляция не доказывает бесполезность или вред. L2-регуляризация уже ограничивает
коэффициенты. Удалять нужно с переобучением оставшихся весов и нормировок, а не
обнулением колонки во время inference.

## Проверяемые вопросы, не установленные ошибки

- Full обучен на 15 205 строках: 7 591 full и 7 614 no_org; у последних отсутствующий
  `h2h_resid` нейтрализован нулём. Это объявленное pooling-решение E-287. Потеря
  различия между отсутствующим org и нейтральным h2h — кандидат на проверку
  missingness-флага/отдельного full fit, но вред pooling не доказан.
- All обучен на отдельном public-корпусе; 97 известных пересечений исключены из
  pro meta cohort. Его full-fit прогнозы backfilled в старые train-карты. Это
  ограничение исторической доступности, **не доказанная in-sample утечка
  meta-target**. Test начинается после последней обучающей метки All.
- Вектор не содержит отдельных признаков возраста истории и полноты покрытия
  ячеек. Metadata `fill/cells/missing_cells` существуют отдельно. Проверка
  сигналов качества/свежести входа имеет конкретный источник данных, но добавка
  к точности пока не измерена. Games/hero_games/pos_games уже описывают объём
  опыта, поэтому объявлять опыт отсутствующим неправильно.
- All уже входит в общую модель. Повторно добавлять его как новую фичу не нужно.
  Early NW поверх full35 уже проверялась в E-286 и не улучшила маленький test.
  Польза Early Win/Late/Lane/kills поверх full35 здесь не доказана; их нельзя
  складывать в общий прогноз на основании согласия нескольких строк панели.

## Зафиксированное сравнение групп

10 вариантов: baseline; без всех draft; без players; без ELO; без h2h;
без 6 interactions; без legacy account ELO/opp_elo и его interactions;
без hybrid_strength; без All backbone и его interactions; без остальных draft.
C=0.1, прежние branch populations, те же 38 test-карт. Нормировки и веса
переобучаются для каждого варианта. Baseline обязан воспроизвести действующие
веса с error<1e-6. Bootstrap по сериям, 2 000 повторов; интервалы описательные,
10 вариантов и повторно изученный test не дают независимого выбора победителя.
Новые reserved/будущие выборки не расходуются.

На момент подготовки preflight дважды остановился с причиной
`local: no conservatively available CPU budget; do not kill existing workloads`.
Ни одна обучающая задача не запущена. Разрешение на разовый однотредовый прогон
запрошено; до него ресурсная конфигурация не менялась.

## Где искать ошибку

- Exact replay доказывает арифметику, но не доступность входа до начала карты.
- В live-delta воспроизводителе специально выбран snapshot до начала карты;
  это контрактный пример на реальной записи, не восстановление старого процесса.
- Интервал после реального старта не доказывает использование live NW/kills:
  они не входят в эти 35 фич. Причину разницы часов надо устанавливать отдельно.
- Коррелированные колонки могут нести полезный остаток. Маленький test и
  множественные варианты могут создать случайного победителя абляции.
- Новая causal history не равна старому production snapshot; границы публикации
  API и восстановленная по end-time доступность — разные гарантии.

Прод, dispatch, веса, калибровка и сервис не изменялись. Результат аудита —
сначала согласовать временной контракт и независимую проверку; удаление/добавление
конкретных фич на этих данных пока не обосновано.
