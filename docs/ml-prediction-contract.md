# Предматчевая оценка и журнал прогнозов

Исправление контракта после E280, 11.09.2026. Веса, пороги и разрешённые
ветки ставки сохраняются; данные E280 не используются для обучения.

`win_model_veto.win_prediction_ex(...)` возвращает `(index, source, details)`
под общим lock. `functions.synergy_and_counterpick` сохраняет снимок `details`
в `ml_win_details` каждого блока. Форматтер, ML-ставка и draft/late-гейты читают
данные этой карты. Старый `win_index_ex` сохраняет пару `(index, source)`.
История по индексу оставлена для совместимости со старыми блоками.

Карточка различает оценку модели и исторический WR. `branch_bet_quote`
использует прежнюю точечную LAN-сетку для full; другие ветки используют WR
своего интервала с округлением минимального коэффициента вверх до сотых.
Нельзя применять full-сетку к короткой ветке. Без собственной калибровки
карточка пишет «исторический WR: нет данных». Исторический WR не гарантирует
будущий результат. Подпись входа называет ветку: например, «без статистики
игроков и очных» вместо вводящего в заблуждение «вход 100%».

`base/prematch_prediction_journal.py` дописывает `runtime/prematch_model_eval.jsonl`
(schema_version=2) для всех посчитанных прогнозов, включая ветки без права
отправлять ставку. Отказы модели также сохраняются. Переменная
`PREMATCH_EVAL_JOURNAL` меняет путь. Запись содержит точный `match_id`,
диагностический `map_key`, игровой таймер, время оценки ELO, ветку, исходную
и скорректированную вероятность, список и значения признаков, missing_keys,
SHA256 загруженного NPZ и snapshot_ts, источник/хеш/WR/цену калибровки.
SHA256 считается по открытому файлу модели: ночная замена пути не меняет
идентичность уже загруженных весов. Время записи не доказывает prematch:
для аудита необходимо проверять таймер и время начала/окончания карты.

Стабильный prediction_id учитывает карту, артефакт, ветку, признаки, вероятность,
калибровку и причину отказа; время опроса не создаёт новый прогноз. Точные
повторы среди последних 20 000 prediction_id подавляются между процессами
и после рестарта; более старый повтор может записаться снова. Процесс читает
новые строки от сохранённого смещения, переиндексируя файл при его замене. Неизвестный match_id
остаётся явным null; series/map_key не используется для соединения с исходами.
Старые строки сохраняются без переинтерпретации.

Завершённые результаты уже существующих путей STRATZ (API и кэш игроков/команд)
дописываются в `runtime/prematch_model_outcomes.jsonl`, переопределение через
`PREMATCH_OUTCOME_JOURNAL`. Поля: match_id, radiant_win, start, end, source,
observed_ts. Отдельных API-запросов и фонового опроса нет: исход появится,
когда его получит существующий сборщик. Конфликт победителя не перезаписывает
первую запись и виден в предупреждении. Пропуски исходов требуют явного учёта
в отчёте; отсутствие строки не означает поражение или незавершённость карты.

Журнал не меняет решение модели при ошибке записи. Ошибка I/O видна в логе;
следующий вызов повторяет попытку. JSON не содержит NaN/Infinity.
